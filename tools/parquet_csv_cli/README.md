# Standalone Parquet CSV conversion

> Bounded Rust conversion with a standalone asynchronous Python supervisor.
> This evaluation is not connected to WEPPpy HTTP routes or production images.

## Overview

The tool converts a supported flat Parquet file to a completed CSV artifact without
Python row objects or whole-output buffering. It preserves the contracted Python
3.12 CSV formatting, field-unit labels and physical-index omission. The harness
stages a private immutable snapshot and owns subprocess cleanup and admission.

Read the [contract](../../docs/schemas/parquet-csv-cli-contract.md) and
[resource ADR](../../docs/adrs/ADR-0148-parquet-csv-evaluation-resource-envelope.md)
for exact supported inputs, failure codes and limits. Unsupported inputs fail;
there is no fallback to the production exporter.

## Build and use

From the repository root on Linux x86-64 with Rust 1.92 and Python 3.12:

```bash
cargo build --release --locked --manifest-path tools/parquet_csv_cli/rust/Cargo.toml
python3 tools/parquet_csv_cli/harness/provenance.py \
  tools/parquet_csv_cli/rust/target/release/parquet_csv_cli \
  tools/parquet_csv_cli/rust/target/release/parquet_csv_cli.json
```

The harness uses only the Python standard library. Rebuild and regenerate the
sidecar after Rust sources, Cargo manifest or lock change. Validation checks both
binary digest and exact source inventory; it does not build automatically.

```python
import asyncio
from pathlib import Path
from tools.parquet_csv_cli.harness import Converter, Limits

async def export():
    binary = Path("tools/parquet_csv_cli/rust/target/release/parquet_csv_cli")
    converter = Converter(binary, Path(str(binary) + ".json"),
                          Path("/tmp/my-csv-scratch"), Limits())
    with await converter.convert(Path("/path/to/source.parquet")) as artifact:
        print(artifact.path, artifact.rows, artifact.bytes)
        # Consume/copy the completed artifact before leaving this context.
        # Context exit deletes private staged input/output and releases admission.

asyncio.run(export())
```

Scratch must be owned by the current UID with mode 0700. All cooperating harness
processes sharing that root share two nonblocking lock slots. The artifact holds
its slot until `cleanup()` or context exit; forgetting cleanup prevents capacity
reclamation. Separate roots have separate budgets. There is no host-wide limit.

## Resource and failure behavior

Defaults: 512 MiB input, 2 GiB CSV, 1 GiB child address space, 120 CPU seconds,
180 seconds each for staging/conversion and 64 descriptors. `Limits` can tighten
memory/CPU/output/wall/staging limits, never raise ceilings. Every input is untrusted even when generated by WEPPpy. Structural page and
metadata limits apply before decoding, including empty and omitted index columns. No core dumps are permitted.

The child accepts fixed arguments with closed stdin. Responses use strict UTF-8
JSON: one versioned success object on stdout, or one handled-error object on
stderr, checked against the exit code. The harness rejects duplicate/unknown keys,
wrong types, nonfinite numbers, encoding errors and trailing content, with a 4 KiB
cap per stream. CSV data remains in the completed file. This is strict JSON
response IPC, not a bidirectional JSON request protocol.

`ConversionError.code` is stable; details and source content are not exposed.
Cancellation preserves `asyncio.CancelledError` after child-group drainage and
scratch cleanup. Cleanup failures retain admission and report `cleanup_failed`;
operators must reconcile failed scratch ownership. The child runs under the
caller's identity and is not an arbitrary-code sandbox. After parent SIGKILL,
reconcile surviving children and abandoned scratch before reusing the root;
normal wall supervision is unavailable after parent death.

Only Snappy/uncompressed flat primitive numeric, boolean and UTF-8 string columns
are supported. Date/time, decimal, binary/nested/extension columns, non-UTF-8
metadata, invalid pandas metadata shapes and duplicate projected labels are
explicitly excluded. Filters and archive extraction are not implemented adapters.
These are limitations for any future integration, not changes to current exports.

## Validation and benchmarks

```bash
cargo test --locked --manifest-path tools/parquet_csv_cli/rust/Cargo.toml
wctl run-pytest --checkout "$PWD" --profile python -- tools/parquet_csv_cli/tests -q
python3 tools/parquet_csv_cli/benchmark.py --corpus /path/to/readonly/corpus \
  --output /tmp/csv-benchmark --repetitions 3
```

Benchmarking additionally requires PyArrow. Every sample runs in a fresh process.
The Python/native comparators intentionally reproduce existing exporter behavior
and do not provide the CLI resource-isolation boundary; use the retained controlled
evaluation corpus, never expose the benchmark runner as a conversion service.
The current exporter, native incremental PyArrow and Rust+harness are compared;
output hashes establish byte parity independently of timing. Native PyArrow's
formatting may differ, so it is a performance comparator rather than an approved
replacement. Retain environment, exact source/binary identity, per-sample metrics
and corpus hashes. Do not benchmark or evict caches on production hosts.

Rust's `peak_rss_kib` is its own process high-water mark. Benchmark aggregation
adds parent and child high-water marks conservatively; it is an upper bound, not
a synchronized peak measurement. CPU metrics and end-to-end wall times have
different scopes, documented in the raw results. See the
[work package](../../docs/work-packages/20261118_parquet_csv_cli/package.md) for
acceptance and reviewed go/no-go evidence.

## Ownership and maintenance

The compact/footer/page scanner and SHA-256 implementation derive from the owned
shape-converter code at `dff2f29f7`; CSV-specific adaptations are local here and
must not be copied back without review. The final Cargo graph and advisory
snapshot are retained with the package, including the transitive Chrono
maintenance warning. Changes to dependency features, metadata handling or resource
ceilings require contract/ADR review and fresh parity/lifecycle evidence.
