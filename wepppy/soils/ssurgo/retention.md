This explicit experimental capability has bounded consumer and installed-controller integration acceptance. The default remains unchanged; broad regression and final release acceptance remain pending. Existing builder calls retain the capped mass-complement behavior. There is no UI, NoDb setting, automatic migration or change to SoilGrids, SIFT, legacy uploads or Roads configuration.

Explicit `SurgoSoilCollection.makeWeppSoils(retention_policy="ssurgo-volume-inverse-experimental-v1", retention_source_receipt=<source acquisition receipt SHA256>)` applies only to eligible selected source horizons. Supply the complete source snapshot and require the exact requested successful profile set; partial success raises. Serialize with the supported default 7778 writer. A policy request with StatsGo or unsupported source data, an invalid receipt, or the legacy writer raises.

All generated opt-in soils carry a policy marker and `.retention.json` companion. Keep the entire project parent chain with its soils. `load_source_companion(path, provenance_root=known_project_root)` validates the actual generated bytes, source identity and derived parent chain. Metadata never supplies root authority. A staged companion alone is insufficient for verification. Moving the complete project preserves relative lineage; do not edit its metadata to repair a failed check.

Actual Disturbed treatment, MOFE stacking and final soil preparation preserve admitted source retention and lineage. Empty/whitespace density lookup cells mean no override under the existing parser. Numeric density overrides, retention recomputation and unsupported depth extension reject. Use fresh output destinations; opt-in soil and companion files are exclusively created and cannot overwrite an existing file or symlink. Default rebuilds must not reuse an old opt-in treatment. Failures may retain partial outputs without success companions; quarantine the attempt and rebuild in fresh storage after fixing the cause.

The representation and eligibility are specified by the whole-soil water capacity contract and the optional retention ADR. A successful file build does not prove native remapping or physical admission. The source volume, native mass fraction, active denominator domains and actual runtime settings require their respective evidence. Do not change the formula or policy eligibility to make a failed project pass.

## Acquisition association boundary

`retention_source_receipt` is a caller-supplied SHA256 identifier. The API checks its syntax and internal source/decision/emitted-row/parent consistency; it does not open or independently verify the acquisition receipt, raw source snapshot or cache. A matching hash is not external source authority, institutional attestation or proof that the metadata describes an actual acquisition.

The authorized acquisition/build caller must independently bind the actual receipt to the complete consistent source snapshot, production cache schema/ordered rows/missingness, selected components/horizons and builder input fields. Retain that association evidence with the build. P04 supplies this separate evidence through its frozen P01 tables and finalized-cache/source-record audit; generic companion validation alone does not reproduce that verification. This boundary remains mandatory for every later opted-in build.
