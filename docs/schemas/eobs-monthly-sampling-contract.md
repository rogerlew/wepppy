# E-OBS monthly sampling contract

This contract applies to the monthly E-OBS rainfall and minimum and maximum temperature means used for CLIGEN localization and served by the metquery monthly endpoint when cubic is requested or omitted. Other datasets and explicit legacy `nearest` and `bilinear` requests retain their current semantics.

## Coverage and sampling

Project the request into raster coordinates and use the containing pixel for the coverage decision. A location outside the raster or a month with missing or unusable data in the containing pixel is unavailable. Ignore cells with a nonfinite value, a band NoData value, or the historical v19.0e `-9999` and scaled `-999.9` rainfall or `-99.99` temperature sentinels as represented in the raster's floating-point storage. Reject negative source rainfall and source temperature below absolute zero as unusable cells. The installed legacy grids can contain partially contaminated values that pass these checks. They cannot be identified reliably from the monthly value alone.

Preserve the existing cubic calculation for each month with a complete, valid 5-by-5 window. Clamp the window to the raster extent when the original window would extend beyond it. When a complete valid window is unavailable, use the immediate two-by-two neighborhood around the query in pixel-center coordinates. Include only in-bounds, valid cells with positive bilinear weight and divide the weighted sum by the sum of those weights. A missing containing pixel prevents substitution even when another nearby pixel is valid. Never search outside that two-by-two window. Reject unavailable support, nonfinite results and temperatures below absolute zero. A finite cubic rainfall undershoot from wholly valid source cells retains the existing response and CLIGEN dry-month handling.

The response retains its existing fields and units, including the requested `Method`. `MonthlyValues` contains twelve finite values in calendar order. A known coverage or result failure returns HTTP 422 with `Code: eobs_coverage_unavailable` or `Code: eobs_invalid_sample`, the catalog dataset identifier, numeric coordinates, and `Month` for a band-specific failure. When the point is outside the raster, omit `Month`. Both GET and POST reject missing, unparseable, nonfinite or out-of-range geographic coordinates with HTTP 400 before opening a raster. A missing, inaccessible or malformed asset returns a sanitized HTTP 503 without filesystem details.

## Consumers and operation

The CLIGEN client surfaces known E-OBS failures with variable, location and applicable month, and retains its existing unit conversions. The E-OBS station ranking and parameter localization callers share this client. Unavailable E-OBS data interrupts heuristic ranking before changing the saved station or publishing a new ranking. The station view keeps its existing failure envelope. CLIGEN station data, generated storm behavior and other datasets are outside this decision. The E-OBS cubic client may use the operator-controlled `EOBS_METQUERY_URL` service base. Set it to `http://metquery:8004/` through the development Compose interpolation environment during the forest replay so the candidate worker and web service use the deployed local metquery. Verify the actual job worker and provider in the replay receipt. When unset or empty, the client keeps its existing public metquery endpoint. Failure at an explicitly configured endpoint does not retry on the public endpoint. Run configuration and request fields cannot override the service address.

When preprocessing new E-OBS rasters, exclude missing source observations from aggregation. Fill missing output cells with the same unscaled value written to GeoTIFF NoData metadata. No existing rasters need rewriting for this fix. See the [parameterization decision](../adrs/ADR-0152-eobs-coastal-monthly-sampling.md).
