# Redis credential transport contract

## Scope and invariants

Redis endpoints are nonsecret: scheme, host (including IPv6), port, logical DB,
and supported TLS/socket query options. Credentials are separate native client
fields or providers. Preserve the existing default user, password, databases,
timeouts, retries, queues, persistence, mounts, identities and secret lifecycle.
This contract changes transport only. It does not authorize a production rollout.

## Resolution and compatibility

Retain each consumer's existing endpoint-variable precedence and defaults.
Python session endpoints retain their independent URL/DB override. Explicit
logical DB selection overrides both URL path and query DB. URL percent escapes
in credentials are decoded once. Preserve ACL usernames as separate fields.

An explicitly configured password file is authoritative; unreadable, empty or
invalid UTF-8 input fails without fallback. Existing surrounding-whitespace
trimming in native clients remains; secret files may end in LF terminators (as generated by existing operator
commands); remove those terminators first. Remaining deployed password bytes
must have no surrounding whitespace, embedded CR/LF or NUL so server and clients
agree. Validate this
restriction before rollout without printing any password. Do not rotate or
rewrite an incompatible secret automatically.

Legacy URL userinfo is accepted at the input boundary, separated immediately,
and never returned by endpoint helpers. If an independently configured password
and a URL password disagree, fail with a constant configuration error. Matching
values use the separate configured credential. Existing legacy password
environment input remains supported but is never synthesized/exported by a
launcher. Explicit password-free local fixtures remain supported when no
credential input is configured; deployed Compose supplies required file inputs.

Malformed URLs, invalid ports/DBs, unsupported schemes/options and credential
query parameters fail explicitly without echoing the input or chained parser
exceptions. Accept redis/rediss TCP endpoints and existing supported Unix socket
endpoints where the installed client supports them. Do not silently downgrade TLS
or drop query settings. Never retain a credential-bearing parsed URL in a cache.

## Native clients and diagnostics

Python helpers expose credential-free endpoint URLs and separate sync/async
connection kwargs or pools. Session storage constructs a client directly.
Credential containers must have nonsecret repr/str; application config and
diagnostic formatting must not enumerate raw credential values. Native driver
kwargs necessarily carry credentials at construction; they must not be logged.
Exceptions at configuration boundaries use constant descriptions excluding input
values. This is not a promise to redact arbitrary interpreter locals or memory.

Go configuration retains a nonsecret endpoint and non-printing credential
provider; constructors receive redis.Options. Streamauth clones options and
preserves its existing authorization-specific overrides (context timeouts enabled,
one-second dial/read/write timeouts, MaxRetries=0), then selects DB 11 for
sessions and DB 0 for revocations. Service clients retain their own existing
timeout/retry settings; authorization must not inherit different service values. Config formatting and errors exclude credentials.

## Workers and dashboard

RQ worker-pool loads an owned config module using the installed RQ config API,
together with `--connection-class wepppy.config.rq_redis.Connection`. The
connection adapter constructs from canonical native kwargs, including username
and socket/TLS options, because RQ 2.12 config handling drops username and
general socket options. The config module must contain no credential values;
the adapter resolves the existing environment/file inputs inside the process. No REDIS_URL or -u credential transport. Readiness uses native kwargs
in-process; argv contains only timing settings. Every owned RQ invocation passes
an explicit empty `--url` alongside config/connection-class options to suppress
Click's `RQ_REDIS_URL` environment default; otherwise URL selection precedes
config loading. The adapter still reads the original environment through the
canonical resolver. A regression must exercise this precedence with both a
legacy RQ_REDIS_URL and config enabled. Preserve DB 9, queue names,
counts, worker classes and startup delay. Review installed RQ behavior for TLS
and options before selecting the adapter; unsupported settings must fail rather
than be silently discarded. Dashboard must also construct its Redis connection
without credential URLs; its sibling source/API is part of the consumer audit.

## Server and CLI

Generate an ACL file in a private runtime directory using umask 077, atomic
replacement and mode 0600. Reference only its path in redis-server argv. The ACL
contains `user default on #<sha256> ~* &* +@all`, preserving the existing default
user's authentication and permissions. Hash the exact validated password bytes
via stdin using tooling already available in the Redis image. Hashes are secret
material too: never publish the file or hash. Preserve current persistence flags
and runtime identity and original umask for persistence files (restrict only ACL
creation). Regenerate on restart; do not touch mounted secrets or
data. Failure to create, protect or consume the file aborts startup.

A small file-aware redis-cli wrapper may use REDISCLI_AUTH only in the ephemeral
CLI child environment. It must validate the file, disable shell tracing, avoid
printing credentials, and never export it into a long-lived parent/application.
This narrowly scoped bridge is subject to independent security review. Health
checks and operator examples call the wrapper with nonsecret arguments. The
wrapper must preserve redis-cli exit status; probes additionally require PONG.

## Acceptance and recovery

Focused tests plus isolated Compose acceptance must prove real AUTH for Python
sync/async/session, Go status/preflight/streamauth, RQ registration and a harmless
job, dashboard and CLI. Verify expected DBs, wrong/missing-file failures, session
expiry, server restart and rollback. Scan rendered Compose, actual process argv,
endpoint/config repr, errors and logs for unique synthetic canaries without
retaining credentials. Mock/miniredis tests supplement but cannot replace AUTH.

Before mutating local services retain nonsecret config/image/identity mappings.
Use isolated names, ports and data for synthetic credentials, never rotate the
shared live Redis or interrupt active jobs. An isolated canonical Compose
overlay must preserve relevant identities, mount structure, settings and
orchestration. Explicitly replace fixed container names, the named wepppy-net
network, host ports and the live Redis data bind; a project name alone does not
isolate canonical development Compose.
Restore only affected services; never flush data or delete existing volumes.
Production deployment remains outside this execution unless separately requested.

## Rationale

Native fields remove unnecessary URL/argv copies without a new dependency or
secret manager. Rejecting conflicting inputs avoids silently connecting under an
unintended identity. Hashed ACL input avoids shell/config password quoting while
preserving the default user's permissions. The short-lived CLI environment
bridge is bounded to tools without a native password-file interface.
