# EDDE v2 future climate in WEPPcloud

## Authority and status

EDDE-WEPP-01 implements the operator's request to execute the integration package after accepting raw EDDE and the precedented CLIGEN hybrid in ADR-0091. Implementation conformance is pending. The experimental client contract, ADR-0091, ADR-0092 and PRISM temperature-ordering contract govern source values and numerical transformations. Existing RQ response, NoDb persistence, climate seed, precipitation scaling and CLI parquet lineage contracts continue to apply.

## Choices and compatibility

Add catalog `future_edde_v2`, label **Future EDDE v2**, ClimateMode.EddeV2=17. Preserve all prior catalog/mode identifiers and defaults. Offer it in current Continental-US and Canada capability profiles and legacy `us`, `canada`, `bc-ca` locale catalogs. Other locales are ineligible. Existing stored capability graphs retain their exact choices until the established explicit refresh. Register additive ordinary and single-input capability structures in a standalone reader-floor ancestor before exposing live writers; do not modify old entries or historical v2 graph generation.

Single=0 and Multiple PRISM=1 only; no Multiple Interpolated. Default spatial selection remains Single. Multiple requires complete finite precipitation/Tmax/Tmin monthly normals at the watershed and every hillslope, with positive reference precipitation, nonnegative target precipitation and ordered monthly Tmin/Tmax at every point. Require matching normal periods/units and retain acquisition identities and hashes. EDDE eligibility alone does not imply PRISM eligibility. No automatic spatial-mode switch.

One required `edde_projection` choice explicitly combines driving model and scenario: `WRF-MPI/SSP2-4.5`, `WRF-MPI/SSP3-7.0`, or `WRF-Nor/SSP2-4.5`. No default projection is silently selected. Require explicit inclusive integer `future_start_year`/`future_end_year`, full calendar years, 2025–2099 for MPI and 2025–2079 for NorESM. These are the initial supported envelope; re-inventory all required monthly objects on every build and reject missing records. Historical is not an application choice. Reuse existing station selection and optional CLIGEN seed semantics: blank omits the CLIGEN `-r` argument (the existing daily-replay automatic behavior); explicit seed passes unchanged. Record null/automatic separately from an explicit seed, without claiming reproducibility for an automatic seed.

Persist additive `_edde_projection` (legacy absent/empty is unselected) and existing future-year fields. A new EDDE build requires a valid selection; selecting its catalog in the UI may precede completion of those fields. Validate source selection, locale, years and spatial mode atomically before enqueue; failure rolls back the parser transaction. Other methods retain their inputs/defaults. Switching away clears EDDE-specific active provenance and cannot relabel old outputs as the new method. A stored but currently unavailable capability remains subject to existing exact-current rules, never bypassing EDDE source/locale validation.

## Acquisition, eligibility and execution

Reuse `build-climate` and its existing tracked RQ job, auth, conflicts, cancellation, timeout and payload replay. No new queue or service. Inventory/transport failures are failed attempts, not data absence to conceal. Cheap local validation happens before enqueue; worker preflight checks all required locations against the selected model's projected land mask before daily weather downloads. Single uses watershed centroid; Multiple also validates every hillslope centroid. No nearest-land relocation or bounding-rectangle acceptance.

Use isolated per-year temporary source caches with the client's existing 4-billion-byte query budget. At most one year's source objects are retained per worker; no shared-cache writer races or unbounded mirror. Query consecutive requested years for watershed daily values, recording each year's source keys, metadata, hashes and extracted CSV before discarding reconstructible cache bytes. Copy source-object attempt/identity diagnostics out of temporary caches on failure; a killed worker must leave a visible incomplete attempt. Preserve point/source and failure provenance under a visible unique `climate/edde-build-*` attempt. Source NetCDF cache bytes are temporary, not required archive payload. Existing RQ timeout bounds the complete job; period bounds and per-year budget bound transfer. Do not add automatic retries or lower-quality fallback.

Collect outside the NoDb lock. Capture projection, years, station/database, seed, spatial/mode/catalog selection, scaling inputs, locales, geometry and PRISM acquisition settings; compare fresh durable inputs under the finalization lock before publication. Changed inputs cause explicit superseded failure. Keep prior published climate/state until complete generated artifacts can be published together. Requested future bounds may change before a build, but the WEPP-consumed `input_years` remains the published climate length until successful finalization, and downstream `calendar_start_year` comes from the active CLI rather than pending request bounds. This prevents failed period changes from relabeling retained WEPP inputs or dates. Retain working/failed/superseded attempts and normal browser/archive access, including across subsequent climate rebuilds. Publish successful files with existing stage transaction and allowlisted derived state only. Build status completion is not proof of artifact correctness.

Generate daily precipitation/Tmax/Tmin with the accepted EDDE adapter; CLIGEN supplies station-derived storm structure/intensity, radiation, wind and dewpoint. Keep existing conversions, rounding and quality guards; no MX .5 P adjustment, bias/elevation correction or quality bypass for this mode. Optional Multiple PRISM uses the existing native daily revision writer and midpoint diagnostics after verifying normals. Prepare final selected CLI files through normal WEPP preparation. Keep NoDb maps, years, monthlies and station parameters consistent with actual generated files. Support existing user-selected None, Scalar, Monthlies and Spatial precipitation scaling with their existing prerequisites and semantics. Reject AnnualMonthlies locally before enqueue: it requires observed-year reference data, which cannot define future EDDE scaling. Complete selected scaling and validate the final CLI files inside the EDDE staging transaction before publication; the router must not apply scaling a second time. Record scaling inputs and the actual final file identities separately from raw EDDE. A scaling failure preserves the previous published files and derived state.

## Presentation, errors and evidence

Use the existing catalog radio, year controls, spatial controls, station/seed controls and one labeled projection select. Show partial Canadian coverage, coarse-grid elevation/bias limitations and hybrid field attribution. Read-only controls remain read-only. Reports/downloads expose actual selected model/scenario/period, requested point/native cell, station/seed, source identities, generation/PRISM diagnostics and build provenance; never infer EDDE location from the station header. Existing browser/download/archive authorization is unchanged.

Local invalid input uses the existing validation error envelope before enqueue. Unsupported locale/projection/spatial/period selections are expected validation failures. Worker errors distinguish native-cell eligibility, missing source records, invalid data/normals, acquisition errors and superseded inputs in retained attempt status and job error text. Do not return successful readiness for failed attempts or hide a previously retained failure.

Acceptance covers absent/empty legacy state, populated selections, preserved older modes/graphs, malformed hostile selections, ineligible land/domain, unavailable records, PRISM-negative locations, partial acquisition, failed CLIGEN, superseded publication and successful rebuild. Exercise real source/grid, CLIGEN, native revision, publication/reload, archive/download and exact prepared WEPP input boundaries. Actual eligible US and Canadian geometry, live submission/worker completion, fresh WEPP output and report readback are required for environment acceptance. No deployment is authorized by this contract.

## Existing PRISM normal product identity

The current Wmesque `prism/ppt`, `prism/tmin` and `prism/tmax` products are the 800 m M4 1991–2020 normal bundle, using monthly millimeters and degrees Celsius. Reference and target points must come from the same acquired rasters. Retain each response's product/acquisition metadata, raster hash and monthly values; reject mismatched product identifiers, missing bands, masked values or invalid normals. This is the existing normal product contract, not a period inferred from EDDE years. Original provider XML metadata verified on 2026-10-14 is retained with the integration evidence. Wmesque does not declare the period in each response; this limitation must remain explicit, and a provider product/period change requires a contract update before acceptance.
