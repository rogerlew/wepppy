# OpenStreetMap road download

The Roads control and TerrainProcessor implement this contract.

From an enabled Roads control a run-authorized user eligible for Roads actions can download mapped vehicular road centerlines within the saved WGS84 project map rectangle. The extent comes only from the run. Reuse the Roads upload area's Pure button, help and polite status patterns. Keep its secondary download action available independently of upload, preparation, and model execution. Explain scope and the optional GIS edit and upload step beside the action. Before the first upload, show a prompt to upload a file. Reveal mapping and model actions after a successful upload. Show progress and a recoverable explanation for empty coverage, missing extent or upstream failure. A download does not activate or replace a Roads input.

The run-scoped CSRF-protected POST endpoint at `api/roads/osm.geojson` returns a UTF-8 WGS84 GeoJSON FeatureCollection attachment. Include attribution to OpenStreetMap contributors and the ODbL source link. Use the existing Overpass client with one bounded foreground download operation, no arbitrary URL, filename or area supplied by the caller. Enforce the canonical Roads action decision, including role, WBT and read-only restrictions, before fetching. Reflect action availability in the control. Use the configured upstream only, disable redirects, bound both extent and decompressed response bytes before parsing, and limit elapsed time and attempts. Errors expose no upstream body or server path. Reject incomplete upstream results explicitly. An empty collection is a successful geographic query; show an empty result in the interface. Report upstream unavailability as retryable. A download requires no new project files or initialized Roads controller.

Both default terrain hydroenforcement and the download select motorway, trunk, primary, secondary, tertiary and their link classes, unclassified, residential, living_street, service, track and road. Keep private-access centerlines and disconnected components. Exclude area=yes ways and pedestrian-only classes. Preserve explicit custom terrain class selections. The download clips to the rectangle and retains line parts only.

Each download feature includes osm_id (way ID as text), osm_highway and osm_surface for GIS filtering, and osm_tags (JSON text containing **every** original tag key and value). Keeping the full dictionary as text avoids collisions and GIS dictionary-field loss. DESIGN, SURFACE and TRAFFIC are editable nullable strings already recognized by Roads. Prefill SURFACE only from a source surface accepted by the existing Roads alias table. A class never establishes drainage design or traffic. Unknowns remain null. Model edits leave source data recoverable. Ordinary and legacy uploads continue through the existing mapping and validation rules.

Acceptance covers unchanged uploaded inputs, exact source-tag round trip and mapped edited values, both cache-independent download and default terrain selection, responsive rendered screen captures, independent usability review and an amended Roads end-user guide.

## Foreground retry and error reporting

One click makes at most two sequential requests to the configured interpreter. After a fast HTTP 429, 502, 503, 504 or dropped connection, wait 4–6 seconds before the second attempt. Honor a longer Retry-After delay (seconds or HTTP date). If insufficient time remains, stop and tell the user how long to wait. The upstream budget is 25 seconds total and at most 20 seconds per attempt. A local network timeout or an Overpass query-timeout remark is terminal. Empty results, invalid input, malformed responses and authorization failures are terminal.

Return a structured timeout (504), an upstream status or connection failure (503), or an invalid upstream response (502). Display the reason, actual attempt count, elapsed time, and server error reference in the existing inline status. Identify a browser deadline separately when the browser receives no complete response in 30 seconds. Log attempt outcomes, upstream HTTP status when known, elapsed time, and scheduled delay without upstream response text. A validation run must click the real button and inspect its output for retry success, exhausted retries and timeout.

The existing run log (ron.log) records the upstream failure and the same reference displayed to the user. The reference also correlates individual attempts in the application logs.
