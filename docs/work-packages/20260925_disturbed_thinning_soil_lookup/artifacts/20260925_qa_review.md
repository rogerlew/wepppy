## Assessment

The production change is small, readable, and consistent with the accepted
[soil lookup contract](../../../schemas/disturbed-treatment-soil-lookup-contract.md).
Both branches test the original class prefix and preserve the shared suffix
resolver. This avoids changing RUSLE custom class keys or PMET/Treatments callers.
Comments explain that boundary without adding an abstraction or exception path.
The deliberate two-branch duplication is reasonable for this bounded correction.

The regression matrix exercises both single-OFE and MOFE paths, formats 9002
and 9005, all 16 catalog thinning variants, generic/custom thinning prefixes,
and all 27 mulch vegetation/severity/level combinations. Real conversion,
MOFE synthesis, preparation, and semantic parsing remain unmocked. Controller
doubles isolate unrelated state; the synthetic slope is explicitly documented
as copy-only evidence and cannot support a model-execution claim.

Expected coefficients come from the effective lookup. Separate operator-value
tests prevent accidental hard-coding, and negative-prefix tests retain existing
missing-row behavior. Intermediate/component/prepared readback checks all OFEs.
The tests do not claim coverage of every soil texture or legacy soil format.

The isolated-project script uses supported fork/treatment operations, refuses
to replace an existing target, records prepared-input hashes and scientific
values, and distinguishes its older local project from the production incident.
Its source-integrity assertion covers top-level NoDb files only. Its revision
field records HEAD, while the separate production-source digest identifies the
implementation file used during validation even if the worktree differs;
neither should be described as proof of deployment.
