## Security Triage Decision

- **Security impact level**: high.
- **Dedicated security review required**: yes.
- **Rationale**: native decoding of potentially hostile file bytes, filesystem
  staging/output, subprocess ownership, resource exhaustion and dependency graph.
- **Threat model**: source Parquet is normally generated by WEPPpy, but every byte
  remains untrusted. Generator labels, filenames, project identity, valid prefixes
  and pandas index metadata grant no validation exemption. The executable,
  checkout and caller's source authorization are trusted. Same-UID malicious
  actors and equivalent filesystem authority are outside this failure boundary.
- **Valid states**: absent source produces an explicit error; valid empty,
  populated, mixed empty/populated row groups, all-null columns and supported
  legacy page offsets retain their contracted output. Unsupported types/codecs,
  non-UTF-8 metadata and other explicitly excluded variants reject without a
  successful artifact. No production workflow or authorization is changed.

## Surface Checks

### 0) Valid-State Non-Interference and User Experience

The compatibility matrix distinguishes valid empty data from malformed metadata.
The empty-file fix does not restore a blanket bypass: every column receives
codec/external-reference/encoding checks, and any physical pages are scanned.
All-null dictionaries may have zero decoded bytes; the positive header length
still advances the scanner, with cumulative/page/count ceilings intact.

The retained legacy data-page alias is narrowly allowed only when the declared
data offset equals the column/dictionary start, a dictionary was observed, and
an actual first data page was observed after scanning the intervening bytes.
Exact ranges, totals and overlap checks remain enforced. Tests reject negative,
out-of-file, overlapping and near-alias offsets. Compatibility exclusions must
remain blockers for any future integration that requires those inputs.

Security approval does not certify numeric/CSV parity or replace the independent
correctness review. Real-corpus byte parity and precision-edge tests are the
separate evidence for those claims.

### 1) Auth, Session, and Authorization

Not changed: no HTTP routes, sessions, tokens, CSRF, run permissions or role
checks are added. The standalone caller must authorize the source path. The CLI
is not an authorization service and must not be used as one in a successor.

### 2) Secrets and Credential Handling

No new credentials or secret mounts. The harness gives the child a minimal
fixed environment. Fixed argv contains only the private request path and limits;
no tokens or source payloads enter arguments or bounded JSON diagnostics.

### 3) Input Validation and Output Safety

OS limits are installed before file parsing. Footer, compact protocol, page,
dictionary, schema and codec validation precede native decoding. Arrow IPC
metadata adds an upstream decoding boundary, covered by footer-size ceilings,
process limits and malformed embedded-schema tests. Zero-trust checks apply
irrespective of generated-file labels.

Output is bounded CSV, not HTML. The contract preserves CSV data rather than
claiming spreadsheet-formula neutralization. JSON control messages have strict
keys/types, finite bounded measurements and 4096-byte captured-stream limits.
Malformed JSON, duplicate keys, overflow and inconsistent output are explicit
failures; no fallback converter or shell interpolation is introduced.

### 4) File System and Run-Tree Boundaries

The harness copies a regular, non-symlink final source into a private snapshot,
checks identity, and never writes to source runs. Child input opens are beneath
the private root with no-follow handling. Output creation is exclusive, private,
and cannot replace an existing file. Staged input digest agreement and final
output regular-file/owner/mode/size checks precede artifact return.

External-column references are rejected even for zero-row input. Final candidate
tests splice real external-reference metadata into files and use inotify to
assert the canary was not opened. Output collision, source mutation, sparse
oversized source and denied/private-root cases have direct checks.

### 5) Queue, Worker, and Subprocess Surfaces

No RQ wiring changes; graph gate is not applicable. Fixed argv/no shell,
process-group ownership, concurrent bounded pipe drainage, timeout, repeated
cancellation and cancellation-during-spawn cleanup are explicit. Admission is
retained until the process group stops and through completed-artifact cleanup.
No numerical-library oversubscription is intentionally enabled.

### 6) Agentic Tooling and MCP Surfaces

No changed MCP or agent execution permissions. Review is confined to the
standalone candidate and documentation. Review fixes do not authorize production
host actions, privileged isolation infrastructure or publication.

### 7) Network and External Integrations

The converter performs no intended network fetches and rejects external Parquet
columns. There are no new services, ports or proxies. This absence of application
network behavior is not a kernel-level egress restriction: an exploited decoder
would retain its process's OS authority.

### 8) CI/CD and Supply Chain

Rust dependencies are pinned and locked; provenance records source, manifests,
lock and binary hashes. No CI publication, production image or deployment change.
The original minimal Parquet approval does not automatically cover Arrow IPC;
the package's dependency assessment explicitly recognizes that additional surface.

The retained audit reports zero known vulnerabilities and the informational
RUSTSEC-2026-0543 warning for unmaintained transitive chrono. Keep the warning in
the final decision; do not label the graph warning-free. The implementation removes
the csv crate in favor of the reviewed owned formatter; attach the final resolved
lock/audit/license inventory rather than relying on the earlier probe graph.

### 9) Data Integrity, Locking, and Concurrency

No NoDb/Redis contracts change. Two file-lock slots coordinate separate callers
using one scratch root and remain held through artifact lifetime. Different roots
remain separate budgets. Source identity/hash checks and exclusive output prevent
accidental mixed snapshots and overwrite. Failed cleanup retains capacity rather
than pretending that resources have been reclaimed.

### 10) Logging, Monitoring, and Incident Readiness

Failure codes and bounded metrics support diagnosis without returning file data.
Child signal termination remains explicit. No success is inferred from file
existence alone. Rollback is removal of the isolated evaluation; it involves no
stack restart. Parent crash recovery and stale-scratch cleanup remain operator
obligations, not hidden automatic deletion.

## Residual Risk and Boundaries

This is hostile-byte validation and bounded failure handling, not arbitrary-code
containment. Same-UID binary/source replacement is outside scope. Decoder unsafe
code and FlatBuffers internals remain in the graph; finite fixtures do not prove
absence of vulnerabilities. Parent SIGKILL can abandon a child and scratch; the
parent wall deadline then ceases to operate. Ordinary limits still constrain the
child, and explicit reconciliation is required before reusing a crashed root.

No test simulates a real uninterruptible kernel wait in a descendant. Source
correctly waits for non-zombie group drainage; ordinary cancellation tests must
not be described as exhaustive kernel-failure coverage. The resource budget is
per scratch root, not a host-wide quota. Unsupported type/codec/metadata variants
and archive/filter adapters remain outside this candidate's compatibility claim.

Follow-up: the separately authorized `parquet_csv_wepppy_integration` package
must address any needed compatibility, actual user-facing workflow, global service
admission, production identity/mount/configuration parity, observability and
rollout. This package grants none of that authority.

## Reviewer Amendment - 2026-11-18 19:08 UTC

**SEC-07 (Medium, process-group observation): resolved in the reviewed temporary
candidate.** A process exiting between opening and reading `/proc/<pid>/stat`
raises `ProcessLookupError` (ESRCH), not only `FileNotFoundError`. The reviewer
reproduced this using a real opened stat descriptor and a terminated/reaped child.
The earlier `_group_alive` handler missed this expected race, so unrelated host
process churn could abort cleanup and leave capacity held.

The fix catches exactly `FileNotFoundError` and `ProcessLookupError` as departed
processes. Other enumeration/read `OSError` values become typed `cleanup_failed`,
without treating denied visibility as proof the process group is gone. Malformed
stat data is not silently ignored. A regression opens a real child stat file,
terminates/reaps that child before reading, observes ESRCH, and verifies the
scanner reports the group absent; a live-group positive control runs first.
A separate injected permission-denial check verifies fail-closed observation.

This is a confirmed cleanup race, but its causal relationship to an earlier
intermittent benchmark-worker failure is **unproven** because that invocation
lost the child traceback. Benchmark tooling now retains failure diagnostics;
subsequent successful runs cannot retroactively establish the lost failure's
cause. Keep the original occurrence and this limitation in the evaluation record.

**SEC-08 (Low, strict JSON conformance and error typing): resolved in the reviewed
temporary candidate.** The earlier shared parser accepted UTF-16/UTF-32 byte
input through `json.loads`, accepted exponent overflow as an infinite float, and
could leak `RecursionError` for deeply nested provenance. The result validator

authority escalation was demonstrated. Malformed provenance was not converted
to the required typed error in the parser-exhaustion case.

`harness/provenance.py:strict_json` now explicitly decodes UTF-8, which together
with the string JSON parser rejects a byte-order mark and alternate encodings.
Its float callback rejects nonfinite exponent results, and its narrow
`RecursionError` translation feeds the existing `protocol_error` and
`provenance_invalid` boundaries. Duplicate keys, nonfinite constants and trailing
content remain rejected. The prepared contract records these requirements before
the implementation change. Fixed argv requests and closed stdin remain unchanged;
the strict JSON claim covers result/error objects and provenance, not a
