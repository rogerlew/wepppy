# EU Disturbed Soil Building Data-Quality Hardening

**Status**: Open (2026-08-19)
**Timezone**: UTC

## Overview

EU disturbed-soil builds can produce WEPP soil files containing zero-valued
parameters or profiles whose horizons are not physically/model-valid. The
current implementation samples ESDAC and EU SoilHydroGrids rasters, derives
Rosetta properties, and writes a `.sol` file without retaining a structured
quality result. The existing integration test checks file creation but does
not exercise known data-quality failures.

This package establishes a reproducible location fixture and then hardens the
builder in evidence-backed phases. Because no known bad coordinates are
available, Phase 0 includes a deterministic search campaign for invalid soils
across the ESDAC footprint. Each phase must leave a runnable test or diagnostic
artifact so the work can be resumed and reviewed independently.

## Objectives

- Capture Marta's problematic coordinates, source samples, generated files, and
  exact failure signatures in a durable fixture format.
- Define explicit validity rules for ESDAC source values, horizon ordering,
  derived hydraulic properties, and WEPP serialization.
- Add deterministic regression coverage before changing production behavior.
- Replace silent acceptance or substitution of invalid data with explicit,
  observable outcomes agreed for the EU workflow.
- Validate the complete path from source sampling through disturbed-soil
  generation and document health, danger, and observation signals.

- Repairing historical run artifacts in place.

## Scope Boundary

Fix confirmed EU soil data-quality failures in the ESDAC-to-disturbed-soil
path without broad refactoring of unrelated soil builders or silently
inventing replacement soil parameters.

## Initial Findings

The source review identified these testable risk points:

- `HorizonMixin` receives values after `isfloat()`, but `isfloat()` accepts
  `NaN` and infinities.
- Zero texture or organic-matter values are accepted; the shared erodibility
  helper can then emit zero erodibility values.
- The builder includes the second horizon unless `h1.depth <= 0`; it does not
  check `h1.depth > h0.depth` or other profile continuity rules.
- Missing Ksat values are skipped, and an entirely missing Ksat profile is
  silently represented with `0.001`.
- The current test in `tests/eu/soils/test_esdac_build.py` only asserts file
  creation and a header, and skips when `/geodata/eu` is unavailable.

These are hypotheses until matched against captured real locations. The first
phase must distinguish actual upstream defects from valid zero-valued soil
properties.

## Phase Plan

### Phase 0 — Random invalid-soil search and evidence freeze

Generate a deterministic, seeded set of 50,000 unique coordinate/pixel samples
over the ESDAC footprint, using spatial strata so the sample is not dominated
by one central-European region. Sample source cells before rejecting anomalous
values, because nodata, zero, and malformed cells are possible targets.
Record raster/data versions, random seed, strata, pixel indices, coordinates,
and screening outcomes.

Run a cheap source-screening pass first, then run the full builder for all
suspicious samples plus a controlled valid sample. Capture exact generated
`.sol` files, raw source payloads, and failure signatures. If Marta later
provides cases, add them to the same fixture and preserve their provenance.

**Exit gate:** every candidate case has provenance and a precise expected
failure or quality symptom, or is explicitly marked as a screened control.
The campaign reports sampled cells, source anomalies, builder failures,
invalid profiles, and valid controls.

### Phase 1 — Captured-location fixture and replay harness

Create a compact fixture containing coordinates plus sampled ESDB categorical
values, STU continuous values, SoilHydroGrids Ksat values, and expected issue
labels. Add a deterministic harness that replays those payloads without
requiring `/geodata` or network access. Keep one optional live test for the
real raster installation.

**Exit gate:** the fixture reproduces each captured symptom and includes a
known-good control. The replay test is stable on a host without EU rasters.

### Phase 2 — Quality taxonomy and invariant contract

Use fixture evidence to define finite-value, texture-balance, CEC-category,
positive-density, horizon-depth-order, field-capacity/wilting-point, and Ksat
rules. Separate invalid source data from valid low or zero values. Define the
per-location result contract: valid, degraded-with-warning, or rejected with
structured reasons.

**Exit gate:** each rule is tied to a fixture case, a downstream WEPP
requirement, or an explicit scientific decision. Any changed default,
threshold, or fallback is recorded for the parameterization ADR gate.

### Phase 3 — Pure validation/result contract and observability design

Add the smallest pure validation boundary that can evaluate a captured source
profile before `.sol` writing. Define the per-location result carrier,
reason-code mapping, batch rejection policy, and diagnostic context including
coordinates, TopoAZ ID, source field, raw value, and reason. Demonstrate the
contract against the captured fixture without wiring it into production
execution yet. Avoid broad exception handling and silent fallback wrappers.

**Exit gate:** the pure validator and contract tests demonstrate all fixture
classes, preserve valid controls, and document the additive worker/batch
interface that Phase 4 will integrate.

### Phase 4 — Production hardening integration

Wire the approved pure validation/result contract into the ESDAC builder and,
if needed, the worker aggregation path. Ensure no invalid `.sol` is written,
partial Ksat data is not silently misrepresented, and errors remain actionable
for operators. Add focused regression coverage and update module/operator
documentation.

**Exit gate:** targeted tests fail before the change and pass after it;
generated `.sol` output contains only finite, ordered, contract-valid values.

### Phase 5 — Disturbed downstream integration

Exercise the generated base soil through EU disturbed transformations and
verify that validation does not reject valid disturbed states or reintroduce
zero/invalid parameters during conversion. Confirm generated run artifacts,
not only in-memory objects, satisfy the soil-file contract.

**Exit gate:** base and disturbed paths pass the fixture matrix, including
  absent/empty/populated/supported-legacy source states where applicable.

### Phase 6 — Observation, review, and callus-softening plan

Run the required correctness and QA reviews, capture baseline and post-change
health signals, and define the observation window. Any temporary diagnostic,
fallback, or retry behavior receives an owner and sunset criteria. Close only
after review findings are dispositioned and documentation matches runtime
behavior.

**Exit gate:** focused and repository validation are complete, evidence is
linked, and any follow-up package or mitigation-retirement experiment is
explicitly recorded.

## Hardening and Callus Softening

- **Failure signature(s)**: the Phase 1 fixture reproduces zero-valued STU
  subsoil parameters, non-increasing cumulative depths (`1200 -> 600` and
  `1200 -> 400`), missing depth classes, all-missing Ksat coverage, and
  `TypeError`, `KeyError`, and `RDIOutOfBoundsException` builder failures.
- **Related prior hardening efforts**: the hardening lifecycle standard and
  the SSURGO intelligent fallback study listed above.
- **Health signals**: confirmed invalid profiles reproduced by tests; 59
  invalid horizon-order outputs in the 1,000-cell pilot; surfaced
  per-location diagnostics; successful valid and degraded controls; downstream
  disturbed-build success rate.
- **Danger signals**: valid locations rejected; degraded cases silently
  accepted; silent fallback rate rises; every source gap becomes a generic
  soil; worker failures lose TopoAZ context; complexity or runtime grows
  without improved evidence.
- **Observation window**: 14–30 days after production deployment, if a
  production behavior change is made.
- **Temporary calluses introduced**: none at scaffold time. Any later
  fallback, warning suppression, retry, or compatibility branch must have an
  owner, review date, and sunset criteria.
- **Callus softening hypothesis**: after stable observation and durable source
  quality, remove temporary compatibility behavior only through a separate
  hypothesis-driven review.

## Random Search Campaign

The initial discovery target is 50,000 unique samples. At that size, a simple
independent-sample approximation detects at least one defect with about 95%
probability when the defect rate is approximately 0.006% or higher, assuming
the sampling frame represents the population of interest. This is a discovery
campaign, not proof that the remaining population is valid.

The sample must be generated from the actual ESDAC raster footprint when the
assets are available. Divide the footprint into spatial strata, draw a fixed
number of unique raster cells per stratum, and use a fixed seed recorded in
the manifest. Do not sample a simple Europe bounding box without a source
footprint check; that would waste samples over ocean and outside-data areas.

The campaign has two stages:

1. **Source screen:** inspect categorical ESDB values, STU texture/physical
   values, depth categories, CEC categories, and all Ksat slices. Flag null,
   nodata, non-finite, zero, out-of-range, inconsistent, or non-monotonic
   source combinations.
2. **Full build:** run `ESDAC.build_wepp_soil` for every flagged sample and a
   fixed control sample. Parse each generated `.sol` and classify the result
   as valid, degraded, rejected, or builder exception. Preserve raw source
   payload beside each classification.

The first run should benchmark a 1,000-sample pilot before committing to the
full 50,000-sample scan. The pilot may adjust worker count or screening
implementation, but not the seed, validity rules, or target sample size
without a tracker decision.
