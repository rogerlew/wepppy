## Freeze the comparison

Record baseline and candidate Git/image digests, host, UTC, serving UID/GID/groups, NFS export/mount alias, scope/incarnation, selected manifest or publication identity, catalog digest and file identity before and after each pair. Select actual projects privately from production on Rocket NFS. Run both implementations with equivalent access, authorized parent context and the same input generation. The candidate runs out of process as an observer. Use an independently enforced read-only project mount, private scratch for outputs and no production queue/cache writes. Preflight the actual read paths and resource limits before starting. Keep path and identity mappings private. Publish counts, hashes, UTC, disposition and redacted reasons.

Budget project count, bytes, elapsed time, per-statement runtime and retries before execution. Process one project at a time. Observe ordinary queue waits and NFS latency against the immediately preceding baseline; stop the observer on resource pressure, unexpected writes or authorization changes. A before/after identity or publication change invalidates the pair. Retry against a stable generation within budget; record exhausted and unavailable cells as open.

## Minimum case matrix

| Actual production case | Evidence required |
| --- | --- |
| Normal project with both assets | Source and logical key for the watershed table and baseline hill loss. Compare actual artifact values and a matched export layer. |
| Normal project with Roads results | For the existing scope-dependent layer, compare baseline versus Roads selection and currentness. An explicit stale or unavailable Roads request must retain its existing unavailable outcome; substitution of baseline data fails the comparison. |
| Omni scenario direct | Include an authorized inherited source and a local override with distinguishable values or digests. Check selected bytes, logical key and each consumer’s own path spelling. |
| Omni contrast direct | Check the local loss output and local merged soils/landuse as controls against accidental parent selection. Include a parent-backed climate or watershed asset. |
| Parent-qualified | Use an actual parent exposing a named child loss key and one omitting it despite the child dataset existing. Compare query visibility and the explicitly qualified export selection separately. Include both scenario and contrast paths. |
| Retained/exceptional | Require a relocated or stale recorded root, a missing optional output and a read-only project. Cover a denied child-to-sibling/outside selection under the query boundary using a non-mutating comparison. One project may cover multiple cells. |

For positive cases require successful independent readback. Two identical errors or empty results cannot provide positive parity. For negative cases compare the expected domain outcome and absence of disclosure. A coverage gap remains recorded; the first-slice gate cannot pass on an unrepresented required class.

## What to compare

1. Read the actual retained catalog and selected producer artifact on wepp1. On wepp2 verify the same digest, schema including units/field metadata, and a deterministic **value-sensitive** query through the pure planner/executor. For example compare hillslope IDs with area, and loss values by hillslope for parent versus child. Choose actual columns from the retained schema, key-sort results and compare typed rows or canonical digests. Record normalized logical key, physical source class and identity. Compare listing multiplicity and lookup for duplicate keys. Observe baseline and candidate listings including unaffected, missing and explicitly denied keys.
2. Run baseline and candidate Feature Export planning/dependency resolution with real production options. Compare geometry carrier, joins, resolved IDs, exact dependency path spelling/order/roles, requiredness, missing markers, catalog metadata signature, actual `content_hash_mode='sha256'` fingerprint and final cache key. On the original read-only inputs, materialize representative joined feature IDs and values through vetted read-only steps in memory or private scratch. Compare both arms. Record a known-good export outcome from the selected project. To verify a fresh export, run the ordinary export pipeline on an isolated writable replay of that same project's snapshot with equivalent identity/mount semantics and private output. Open the delivered layer and compare geometry, CRS, feature IDs, columns, units, representative values and manifest dependencies. The replay supplements the mandatory actual-project read. Byte-for-byte ZIP equality is unnecessary where metadata is nondeterministic.
3. Use only vetted read-only paths on live projects. Query context resolution can invoke a freshness barrier even with `auto_activate=False`. Export submission preparation can hydrate NoDb state or call a getter; normal export execution publishes files. Use detached, verified read-only bindings for required controller selections. Mark a cell open if equivalence cannot be established without mutation. Run producer publication, replacement, deletion and normal writer/reader entry points on private production-derived replays only.
4. Record independent correctness and security review for the exact candidate and artifacts. Every mismatch records the baseline, candidate, impact, owner and resolution. Stop and preserve evidence on a discrepancy; restore the prior shadow selection and repeat affected cases after correction. Never repair an original project to manufacture parity. Keep counts of pass, fail, inconclusive and uncovered by cohort and consumer. A production-shadow pass establishes parity for this slice, not fleet throughput or rollout authority.
