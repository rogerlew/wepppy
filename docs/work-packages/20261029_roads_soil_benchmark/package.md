# Roads soil and binary benchmark

Status: Complete (2026-10-29 21:51 UTC); no production candidate accepted.

## Objective and accepted scope

Investigate Marta's concern that WEPPcloud Roads produces too much sediment.
The operator requests order-of-magnitude similarity to fswepp2 WEPP:Road with
`wepp2010`, using **soils generated by WEPPcloud** and **`wepp_261026`** for
the candidate, across different climates. Modern soils does not mean merely
converting legacy road templates to a newer format.

Determine which defensible road-property adjustments to generated soils produce
comparable results. Exact parity is not required; the reference is not measured
field truth. Avoid climate-specific tuning or an arbitrary sediment multiplier.

## Experiment and acceptance

Separate binary, soil and assembly effects: legacy inputs with `wepp2010`, the
same inputs with `wepp_261026`, then generated soils with `wepp_261026`.
Hold geometry, management, climate bytes, duration and metric definitions fixed
within each comparison. Test management differences separately, then exercise
the eventual candidate through actual Roads preparation.

Initial study interpretation of order-of-magnitude similarity: positive
candidate/reference ratios from 0.1 to 10. Report each case and climate/design/
surface/texture group, absolute differences, runoff and annual variability.
Separate detachment from sediment export. Report zero and near-zero denominators
explicitly without an arbitrary epsilon. Do not average away failing groups.
This criterion is experimental, not a new production threshold.

Candidate climates are retained Birmingham AL, Denver CO, Flagstaff AZ and
Charleston WV inputs in `/workdir/fswepp2/parity-runs/wepproad/`, plus
`tests/roads/data/site.cli`. Verify actual calendars and common duration within
each pair. Cross climates with traceable generated soil specimens rather than
changing soil and climate simultaneously. The four selected generated specimens and their provenance are recorded in the report.

## Boundaries and rationale

Preserve the historical 516-case report and production parameterization during
discovery. Candidate promotion requires an ADR, Roads specification changes,
generated-input readback and fresh isolated project execution. Study selection
of `wepp_261026` does not change deployment defaults.

Complexity budget: existing native binaries, soil builders, runners and matrix
tools; no new dependency, service, queue or infrastructure. Security impact:
none for isolated scientific inputs and local execution; dedicated security
review is not required for this scope. Exclude account metadata from fixtures.

Fidelity target: scaffold/surrogate discovery with faithful reference inputs.
Scaffolding is not production completion. Implemented and wired are separate
states; wired acceptance requires consumed input and generated project output
evidence from the candidate binary and the actual Roads preparation path.
