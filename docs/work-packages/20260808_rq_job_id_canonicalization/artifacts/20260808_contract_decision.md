# Contract Decision – Canonical RQ UUID Job IDs

**Date**: 2026-08-08
**Starting revision**: `212c8d80b7c46be4119f616c86d426d69778ad35`
**Operator**: repository operator in this conversation
**Implementer**: Codex

## Decision

New UUID-based RQ job IDs generated by WEPPpy use the hyphenated
`str(uuid4())` representation. Preallocated IDs use one shared helper. Every
lookup, metadata, URL, and UI boundary treats the stored ID as an opaque exact
string and does not add or remove hyphens. Existing bare-hex records remain
readable until expiration.

## Rationale and Compatibility

RQ 1.16.2 defaults to `str(uuid4())` and accepts supplied IDs as exact strings.
The prior mix arose from atomic workflows using `.hex`; a dashboard workaround
then corrupted those exact IDs. Canonical generation restores consistency;
exact pass-through preserves old jobs. UUID entropy and response keys do not
change.

## Rejected Alternatives

- Normalize punctuation at lookup: ambiguous and changes exact Redis keys.
- Continue permitting both formats for new jobs: perpetuates the defect.
- Rewrite existing Redis records: unsafe and unnecessary.

## Regression Evidence

Test helper output, all preallocated enqueue paths, both dashboard ID forms,
serialized child/receipt links, migration, fork/finalizer paths, and the RQ
dependency graph. Implementation conformance is pending.
