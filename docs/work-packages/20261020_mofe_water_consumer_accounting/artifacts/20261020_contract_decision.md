## New evidence that prevents source ratification

The [paired readback](20261020_paired_source_readback.json), generated by
[paired_source_readback.py](paired_source_readback.py), covers 328,800 MOFE
terminal-day rows in `up-pedantry`. There are no duplicate daily identities,
unmatched PASS days, or changing/invalid OFE areas in this comparison.
On 1,096 days terminal WAT Q is positive while PASS runvol is zero. The largest
difference is 0.9952729 mm (hill 156, 2023 day 283, SUBEVENT). EVENT-day maximum
difference is 0.0026864802 mm; printed precision must be assessed separately.
The receipt binds both Parquet hashes. Configured `wepp_250915` is an observed
NoDb value, not proof of the exact executable that produced these files.

Current `wepp-forest/src/wshpas.f90:139` emits surface runoff in an EVENT only
when internal terminal `runoff >= 0.001 m`. SUBEVENT and NO EVENT omit surface
runoff. The threshold is on internal runoff, not printed terminal WAT Q:
ordinary WAT Q additionally multiplies by `efflen/totlen`. Do not recreate the
PASS threshold by testing `Q >= 1 mm`. Lateral PASS also has a small-volume
SUBEVENT threshold. WAT local budgets and exported watershed volumes therefore
cannot be assumed numerically identical, even with exact geometry.

`contin.for:1262-1268` gives pre-filter surface volume as terminal WAT Q times
`fwidth(1)*totlen(nplane)/1000` for ordinary and contour branches.
`input.for:380-389` enforces constant width in hillslope modes. Thus that area
equals summed local OFE areas for the inspected hillslope writer. Variable-width
custom/legacy Parquet lacks this proof; numeric Q/QOFE equality is not lineage.
Current source inspection alone does not certify all archived binaries.

The prior isolated ET/Dp validation project has H.wat only and cannot certify
paired WAT/PASS behavior. It remains historical evidence for its original scope.

## Pending operator choice and compatibility implications

The operator has been asked whether corrected hillslope reports, dashboard,
daily Ash inputs and exports should represent physical terminal WAT runoff or
threshold-filtered PASS-exported runoff. This is a scientific product choice,
not a rounding issue or a new implementation detail implied by execution.
Canonical amendments and the formula ADR await this answer.

If WAT is chosen, retain subthreshold hillslope water and explicitly distinguish
it from named watershed Runoff. Require supported producer/geometry provenance
for terminal-Q normalization. If PASS is chosen, explicitly specify its new
source dependency, absent/legacy behavior and threshold effect on Ash inputs.
Neither choice permits changing WEPP physics or inferring a missing outlet as
zero. AshPost subtraction must use the PASS contribution already represented
in its watershed source, even if the chosen hillslope product uses WAT.
