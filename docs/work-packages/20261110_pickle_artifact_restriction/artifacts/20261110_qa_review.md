## Implementation assessment

The patch is small and follows existing interfaces. Bootstrap rejects through
shared path admission before blob access and uses a name-only Git diff for pickle
admission across ref updates and introduced commits. Browse removes
the unsafe reader and advertisements, then handles pickle preview rejection and
explicit raw byte delivery before text parsing. D-Tale centralizes its existing
suffix check in a small helper used before downstream work. Its internal loader
rejects before fingerprint/cache acquisition; the reader and stub are deleted.

No new runtime dependency, fallback parser, configuration flag, broad exception
handler, queue, persistence mechanism or cross-service coupling was introduced.
Duplicating the two forbidden suffixes at separate process boundaries is modest
and clearer here than introducing shared runtime machinery. Retired archive
semantics remain unchanged, as documented in the supplemental checkpoint.

## Merge and stub follow-up

Security reproduced a merge-admission bypass after the initial review; that
approval was reopened. The first two real pushes unexpectedly succeeded
(`red-merge.log`). Expanded red evidence (`red-merge-expanded.log`) covers both
merge parent orders and an already-reachable fast-forward: six forbidden cases
failed while three allowed text controls passed.

The bounded fix adds `_validate_pickle_changes`. It examines NUL-delimited
name-only AMT diffs with rename detection disabled, so a renamed destination is
still checked. It checks every destination ref even when no commits are newly
introduced, and checks intermediate introduced commits. Only pickle admission
uses this extra scan; existing merge parser/ref/deletion/logging behavior is not
expanded. Each test baseline contains an unchanged legacy pickle, proving the
fix does not impose a blanket whole-tree ban. Final Bootstrap evidence is
27 passing tests; total focused evidence is 205 passing tests.

The D-Tale stub synchronization was checked against existing runtime:
`DatasetMeta` fields and `_build_instance_response` keyword-only parameters
