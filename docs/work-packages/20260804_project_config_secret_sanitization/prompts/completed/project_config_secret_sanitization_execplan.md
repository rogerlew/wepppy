## Purpose / Big Picture

Future project-owned configs will copy effective runtime options into project
roots and archives. WP00A makes that safe by removing stale credential material
from the source corpus and providing one fail-closed, redacted gate that later
writers can call before publishing those artifacts. No writer is enabled here.

## Context and Orientation

Shared configuration lives under `wepppy/nodb/configs`, including current
`.cfg` presets, `_defaults.toml`, legacy `.toml` snapshots, and one batch
config. The new `wepppy/project_config_sanitization.py` module scans INI-like
config bytes and JSON manifests before materialization. “Materialization” means
writing generated bytes into a project root or archive. The CLI at
`tools/check_project_config_secrets.py` applies the same rules to repository
sources, project trees, and ZIP/tar archives without extraction.

## Validation and Acceptance

Acceptance requires zero scanner findings in all 270 tracked sources, explicit
rejection of synthetic generated configs and manifests, rejection inside both
ZIP and tar archives, redacted diagnostics, focused test success, and no
unresolved high/medium security finding. No flattened writer may be enabled.

## Idempotence and Recovery

Scanning is read-only and repeatable. Credential removal is a small tracked
diff. The gate reads archives without extraction or mutation. A failed scan
returns nonzero and names only source/location/key/rule, so a corrected source
can be rescanned safely.

## Interfaces and Dependencies

`assert_materialization_safe(config_text, manifest_text=None)` is the pre-write
API. `scan_config_text`, `scan_manifest_text`, `scan_path`, and `scan_archive`
provide inspection. `ConfigMaterializationError` exposes redacted violations.
The module uses only the Python standard library.
