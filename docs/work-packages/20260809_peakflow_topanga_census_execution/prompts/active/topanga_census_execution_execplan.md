## Validation and Acceptance

The package passes only when the frozen plan file and ID match preparation,
the selection contains exactly 1,088 eligible unique IDs, and all selected IDs
have current complete terminals whose binding hashes and artifacts validate.
Every trial must change exactly one declared input and realize its expected
value without clipping or serialization loss. Terminal, event-pair, candidate,
and prevalence totals must recompute from immutable evidence and agree across
scenario, family, direction, and overall grains.

Planning is not rerun to authorize execution. Event pairing remains an outer
join; baseline-only and mutant-only rows remain null on the absent side and
retain presence flags. A byte-identical repeat of aggregation must produce the
same compact summaries. No full-census GO is inferred from a partial terminal
set. No routing or downstream-impact statement is accepted.

The security gate fails if any path escapes its root, any symlink redirects a
read or write, any executable or input hash drifts, the selection introduces an
unapproved ID, subprocess arguments receive shell interpretation, concurrent
workers share a trial directory, retry overwrites prior attempts, or aggregation
reads an unvalidated artifact. The scientific gate fails if mutation values,
screening floors, event keys, null meanings, denominator definitions, or frozen
eligibility change.

## Idempotence and Recovery

Preflight, selection generation, dry-run, and aggregation are deterministic and
safe to repeat. Do not overwrite the frozen preparation plan or execution
selection. If a legitimate preregistration input changes, stop and return to a
new preparation disposition rather than modifying this package in place.

Execution writes only below each trial's plan-derived evidence locator. Atomic
terminal writes and preserved `terminal.attempt-*`, `runs.attempt-*`, and
`output.attempt-*` paths are the recovery authority. A crash leaves complete,
failed, stopped, or absent current terminals distinguishable. Resume only under
matching bindings. Never delete an attempt to make counts reconcile. Aggregate
only after terminal reconciliation, and write ledgers through temporary files
plus atomic replacement.
