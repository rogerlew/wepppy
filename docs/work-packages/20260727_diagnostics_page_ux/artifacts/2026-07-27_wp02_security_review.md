## Security Triage Decision

- **Security impact level**: `high`
- **Dedicated security review required**: `yes`
- **Triage rationale**: WP02 makes a caller-local session mutation endpoint available before authentication and therefore widens the anonymous attack surface.
- **Threat model assumptions**:
  - A hostile site may attempt to force a victim's browser to clear its WEPPcloud session.
  - A direct caller may invoke the endpoint repeatedly but cannot supply a user, session, cookie, or run identifier.
  - Browser storage is origin-scoped; the client can remove only keys accessible to the current WEPPcloud origin.

## Surface Checks

### 1) Auth, Session, and Authorization

- [x] Anonymous access is intentional and limited to clearing the caller's own Flask session/cookies.
- [x] Global CSRF validation applies to the mutating route.
- [x] The client obtains a usable anonymous token from `base_pure.htm` and submits `X-CSRFToken`.
- [x] Explicit normalized same-origin enforcement rejects cross-origin and missing-origin/referer requests.
- [x] No token, session count, user identity, or auth internals appear in the success response.

### 2) Secrets and Credential Handling

- [x] No secrets, credential defaults, secret mounts, or token logging changed.
- [x] The reset client never reads cookie values.

### 3) Input Validation and Output Safety

- [x] The endpoint accepts no user-controlled identifier or body field.
- [x] Template data attributes are generated by `url_for`; status text uses `textContent`.
- [x] The JSON response is fixed to `ok`, `login_url`, and a generic message.

### 4) File System and Run-Tree Boundaries

- [x] No file-system or run-tree reads/writes were added.

### 5) Queue, Worker, and Subprocess Surfaces

- [x] No queue, worker, dependency-edge, or subprocess behavior changed.

### 6) Agentic Tooling and MCP Surfaces

- [x] No agentic or MCP production surface changed.

### 7) Network and External Integrations

- [x] No outbound call or external integration was added.
- [x] Rate limiting was considered: reset is cheap and caller-local; CSRF plus same-origin checks address forced-logout abuse, so a dedicated limiter is not justified.

### 8) CI/CD and Supply Chain

- [x] No workflow, dependency, package, or supply-chain behavior changed.

### 9) Data Integrity, Locking, and Concurrency

- [x] Reset clears only the request's Flask session and emits deletion headers for configured caller cookies.
- [x] Repeated or concurrent calls are idempotent and cannot address another session.
- [x] Client storage clearing is prefix-scoped and leaves unrelated origin storage intact.

### 10) Logging, Monitoring, and Incident Readiness

- [x] No sensitive values are logged.
- [x] CSRF and same-origin failures remain explicit 400/403 responses.
- [x] Rollback is limited to restoring the anonymous 401 and profile placement; no persistent schema/data migration exists.
