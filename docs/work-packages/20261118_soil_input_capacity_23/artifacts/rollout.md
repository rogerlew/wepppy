# Linux capacity-23 release and rollback

Release is opt-in. Keep default executable aliases and saved project selections
unchanged. Native source uses mxhzin=23 and mxnsl=10. No conductivity or horizon
merging policy changes. Capacity is bound to matching role sidecars and binary
SHA-256 identities; historical undeclared capacity remains ten.

Before activation, integrate the reviewed WEPPpy task with commit-preserving
history and retain the remote integration receipt. Deploy using the installed
production wctl preset and scripts/deploy-production.sh, following its retained
candidate preflight. This package does not authorize an alternate image or
Compose workflow. Retain exact prior deployment identity and both binary roles.

After activation, explicitly select the new pair on a disposable copy first.
Build soils, inspect the 200 mm split and all retained horizons, prepare all
hillslope/channel inputs, execute fresh hillslope and watershed runs, and read
full-calendar outputs and report artifacts under production worker identities.
A successful job alone is insufficient. Only then explicitly change the affected
original project's selection and rebuild/rerun if the operator requests recovery.

Rollback uses the canonical retained deployment and prior matched pair. A project
that already contains more than ten input horizons cannot simply be switched to
an old executable: the new pre-launch guard must reject it. Preserve its prior
artifacts and diagnose; do not truncate/merge horizons to make rollback run.
Restore a coherent known-good project snapshot or keep the compatible pair until
repair. Never mix role builds, reuse candidate PASS files under another build,
or interpret restored deployment health as successful model recovery.

Production activation and original project repair have not been performed.
