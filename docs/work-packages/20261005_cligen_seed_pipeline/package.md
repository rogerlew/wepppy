# CLIGEN Seed UI-to-Execution Pipeline

**Status**: Open - contract checkpoint in progress (2026-10-05)
**Timezone**: UTC

## Overview

Add an advanced Climate Options field for an optional CLIGEN random seed,
persist that choice in `climate.nodb`, and carry an explicit seed through every
CLIGEN-producing path owned by the Climate NoDb controller. Blank and omitted
values retain current automatic/default behavior; explicit values make climate
generation reproducible and inspectable at the final process boundary.

## Objectives

- Expose an optional integer CLIGEN seed in Climate Options advanced settings.
- Validate and persist the seed as `_cligen_seed: int | None` in `climate.nodb`.
- Carry an explicit seed unchanged through request parsing, RQ payload replay,
  build snapshots, helpers, and every applicable CLIGEN command.
- Keep current behavior when the setting is absent or blank.
- Prove the complete path with unit, route, frontend, process-command, and
  actual-project integration evidence using `canine-liar`.

## Scope

### Included

- Climate control template, controller serialization coverage, rq-engine
  climate input handling, Climate NoDb parsing/persistence, and build helpers.
- Vanilla, modified stochastic, observed, future, interpolated, and
  single-storm CLIGEN paths reached from the Climate controller.
- Multiple-climate snapshot fencing so a changed seed supersedes stale output.
- Canonical user-facing climate seed contract and Climate Options help.
- Direct generated-output evidence from the vendored CLIGEN executable.

### Explicitly Out of Scope

- Changing CLIGEN's random-number algorithm or accepted native seed syntax.
- Adding a global seed shared with WEPP, soil, landuse, or other generators.
- Changing the default when no explicit seed is supplied.
- Production deployment or mutation of projects other than the authorized
  `canine-liar` validation project.

## Complexity Budget

- **Existing mechanisms reused**: Pure UI form serialization, rq-engine climate
  route, `ClimateInputParsingService`, NoDb locking/dump, existing build input
  snapshot, and current CLIGEN adapters.
- **New mechanisms permitted**: one additive field/property and seed arguments
  on existing Python interfaces.
- **Simplest plausible change tested first**: pass one validated optional
  integer through existing calls without a new service or store.
- **Real acceptance condition**: `canine-liar` persists an explicit seed, a
  fresh build runs the vendored executable with `-r<seed>`, and output/log
  evidence is read back.
- **Evidence required before escalation**: retained failure showing an existing
  call boundary cannot carry the integer.
- **Explicitly prohibited expansion**: new queues, services, datastores,
  dependencies, protocols, or deployment topology.

## Compatibility and Data Plan

This is an additive NoDb field contract over a field already present in current
objects. Legacy files without `_cligen_seed` are treated as automatic. An
omitted request field preserves the stored value; a present empty field resets
it to automatic; an explicit integer in `0..99999` replaces it. Existing
automatic behavior remains path-specific: callers that currently omit `-r`
continue to omit it, while paths that currently allocate a persisted random
seed retain that allocation behavior. Explicit values always override those
defaults and are never silently replaced.

Downstream regression evidence must cover payload rollback, NoDb reload,
enqueue metadata replay, multiple-build snapshot comparison, every adapter
family, and the exact subprocess command. Generated climate output must be
parsed after the real build.

## Security Impact and Review Gate

- **Security impact triage**: `low`
- **Dedicated security review required**: `no`
- **Rationale**: The field is a bounded integer carried through an existing
  authorized route and argv list. It adds no shell interpolation, path input,
  permission, credential, or network capability.

## Generated Artifact Validation Gate

- **Applicable**: yes; CLIGEN creates the `.cli` consumed by WEPP.
- **Intent evidence**: submitted climate payload with an explicit seed.
- **Persisted-state evidence**: reload `Climate` from `climate.nodb` and read
  the exact integer.
- **Prepared/consumed-input evidence**: CLIGEN log or captured argv contains
  exactly one `-r<seed>` argument.
- **Execution output**: a fresh `.cli` generated by the vendored binary parses
  successfully.
- **Actual-project evidence**: authorized local project `canine-liar`.
- **Highest permitted claim**: locally validated; deployment remains separate.

## Risks and Stop Conditions

Stop if a blank field changes existing seed behavior, if any worker derives a
different seed, if a malformed value partially mutates `climate.nodb`, or if
the real executable does not receive the persisted integer. Do not claim
determinism from persistence or mocked argv alone; compare fresh output from two
otherwise identical explicit-seed runs.

## Deliverables

- Canonical CLIGEN seed control contract.
- UI, NoDb, RQ replay, snapshot, helper, and process wiring.
- Focused and end-to-end tests plus retained `canine-liar` evidence.
- Completed correctness review, tracker, and ExecPlan.

## Rollback

Revert the implementation as one change set. Existing NoDb files remain
readable because `_cligen_seed` is already optional runtime state; the UI field
and explicit forwarding can be removed without migrating stored projects.
