## Live exercise

1. Read back actual candidate container mounts, worker groups and registration under its production identity. Check one dedicated consumer alongside the independent fork/archive worker. Record ready depth and queue-head age on default, batch, fork-archive and query-catalog. Check for a catalog callable on any default consumer.
2. Create two exclusively owned test projects on Rocket. Write a small known Parquet asset on the catalog project and deterministic bounded payload files on the archive project. Use the ordinary archive job on the latter for a no-catalog control. Validate the ZIP integrity, payload bytes, RQ origin and worker.
3. Exercise the actual managed receipt and production admission path. Run the same archive on the separate project during catalog activity. Verify a positive intersection of actual RQ execution intervals on independent workers. Verify matching receipt acknowledgment, zero pending receipts on the canary, catalog file contents, schema and fixture values on both hosts. Record queue waits, job durations, exact canary receipt age and Rocket client RPC counts/latencies alongside the control. Client mount counters include other host traffic.
4. Use at most one repeat if natural job durations miss overlap. Stop issuing work on unexpected queue pressure, failed fixture ownership, worker mismatch or artifact failure. Limit the exercise to 15 minutes and retain timeout evidence. Keep the oldest sampled dirty receipt separate from the exact canary acknowledgment latency. A one-worker canary cannot establish sustainable arrival/service rates or achievable fleet freshness.

The control uses archive creation, which verifies the real fork/archive worker while avoiding the filesystem-wide retention reconciliation that production restore can trigger. Production acceptance results follow.

## Serving cutover on November 23 UTC

The operator accepted the image-specific scan findings. The wepp1 build and both peers verified common image `sha256:b6e0462f8a749eabb168ea398a4f8056c46305f2a003e04b026c0d5623567c94`. The same-database scan of this image and its predecessor found 87 critical and 679 high Grype matches in each, with identical advisory sets and severities. Both npm reports had four high findings. Native scientific advisory coverage remains limited.

An expiring catalog pause fenced new admissions. Six active default jobs matched the exact legacy refresh function and ledger and received stop commands. All queues showed zero started jobs before activation. The three host deployments passed their image, stability and worker checks. Before thaw, both dirty indexes contained 1,757 locators and the old-minus-new difference was empty. The wepp1 producer matched exactly one dedicated wepp3 registration. The catalog pause and RQ suspension both cleared. The fleet registered 12 default, eight batch, one fork/archive and one catalog consumer.

At 06:34 UTC, a fresh managed Parquet receipt waited 0.053 seconds in RQ and reached published acknowledgment in 0.732 seconds. Both clients verified zero pending receipts, the expected schema and values 31 and 47, and catalog digest `840f51569ceb99f01aad1d7a9ef8ccb315f3cc416a29765bfc209f6df7106425`.

The control archive waited 0.057 seconds and ran for 2.251 seconds. The first overlap observation found inventory holding the catalog worker throughout its 120-second refresh window. The repeat verified 0.610 seconds of actual overlap with that inventory job. The archive waited 0.050 seconds, completed in 0.610 seconds, and passed ZIP integrity and fixture byte checks. The individual refresh and concurrent inventory/archive runs are separate observations. Wepp3 READ RPC mean RTT was 0.441 ms across 34 operations in the control window. The overlap window contained only one READ and is too sparse for a latency comparison. See the private acceptance directory's `live-summary.json` for all operation counts and timings.

The oldest sampled outstanding receipt after activation was 16.9 days old across 16 randomly sampled dirty paths. During the inventory observation, six directories had completed and 10,820 entries had been counted. A fresh fixture can publish quickly while older work still waits for the single slot. Re-evaluate oldest receipt age, inventory handoff time and service rate before changing the worker count or after migration to wpc1.
