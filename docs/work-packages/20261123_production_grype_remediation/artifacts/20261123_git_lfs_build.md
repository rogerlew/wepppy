# Git LFS Debian package qualification

The common production and development builds now install `git-lfs 3.8.1+wepp1`. Both use the same digest-pinned Go 1.26.11 builder as the esbuild repair. The package script verifies the upstream Git commit, selects the six reviewed module updates and checks the resulting go.mod and go.sum against independently qualified hashes. Upstream Debian packaging generates the help text, translations, hooks and package metadata. The compiler and packaging tools stay in the build stage. [Git LFS source](https://github.com/git-lfs/git-lfs/tree/a662a6dbfedf706cfa9fc7a5b7bcc7ba2e2c8a65)

The official 3.8.1 archive and upstream Debian package passed a real transfer but retained 14 module findings on the frozen Go database. The stock binary introduced a compression dependency with a listed fix. A direct source build with the fixed modules passed transfer but omitted help and translations. The packaged repair returned zero module findings, matched all 36 upstream help responses and the Spanish diagnostic, and preserved the production system-wide Git filters. Its installed binary SHA-256 is `0f14e8eda62ca92d5e25b4604fc9db7bef5356e4e2417886e1e23908603c48de`. [Independent Go review](20261123_go_reachability_review.md)

In the combined component trial under UID 1002 and GID 130, the production Git LFS pull materialized all 15 Rosetta objects at commit `1c22335ee0e4055f45adb3e597e5bf49cd9a2c88` from both a read-only local remote and the upstream HTTPS remote. Every file matched its counterpart in the reviewed scientific image. Git LFS verified the objects and PyArrow read 4,640 rows from Ann.parquet. The component trial image is `sha256:a15b02e3cad5dc673ee6302a1d38f6446150fc5ee344b835ef58f84607e00d1d`. Private receipts include `round2/component-readback.log`, `round2/git-lfs-final-scan.json`, `round2/rosetta-https.log` and `round2/combined-consumers.log`.

Future rebuilds must retain the reviewed Go module inputs and upstream-generated command help. The Debian package build omits upstream tests during image construction. Qualification exercised the installed binary through Git hooks, push, clone, pull, content readback, help and localization. Reassess the private package when an upstream build includes the fixes.
