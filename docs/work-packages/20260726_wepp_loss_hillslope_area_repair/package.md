# WEPP LOSS Annual Hillslope-Area Repair

**Status**: Closed (2026-07-27)
**Timezone**: UTC

## Overview

This incident package repairs the native WEPP watershed LOSS interchange for
annual hillslope rows that contain the same `Hillslope Area (ha)` field already
declared by the average annual table. The current WEPPpyo3 parser expects 11
fields, but production WEPP emits 12, causing post-watershed interchange job
`e1598864-a1e5-40f6-9cd4-25bbf55afe67` to fail.

## Objectives

- Parse both the historical 11-field and production 12-field annual hillslope
  contracts without weakening strict column validation.
- Publish `Hillslope Area` additively in
  `loss_pw0.all_years.hill.parquet`, with existing columns unchanged.
- Audit WEPPpy consumers for named and positional schema assumptions.
- Build, validate, commit, and push the canonical py312 WEPPpyo3 release.
- Complete independent code and QA reviews and disposition every finding.

## Scope

## Compatibility and Regression Plan

This is an additive parquet schema mutation. Existing annual hillslope columns
remain stable and `Hillslope Area` is inserted at the semantic source position,
between `Sediment Yield` and pollutant fields. Named-column consumers remain
compatible. The audit must identify any positional reads, strict full-schema
comparisons, serialization projections, or aggregations and validate them
against output generated by the rebuilt native extension.

Regression coverage uses the exact production row shape and asserts field
count, name, type, unit, and value. Historical 11-field rows normalize to a
null area while preserving pollutant positions. Every other width remains an
explicit failure rather than becoming a silent fallback.
