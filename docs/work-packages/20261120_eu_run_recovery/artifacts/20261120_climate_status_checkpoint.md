For a returned accepted submission the panel follows its job ID. On reload the panel uses the verified creation order of the existing run-scoped RQ records. Pending, successful and failed jobs use the same ordering. An indeterminate, mismatched or expired record is unavailable. Render the current climate summary separately when there is a climate file. Preserve the already rendered summary and current filename while an attempt is pending or rejected. Successful completion refreshes both from server-rendered metadata. Ignore tagged diagnostics and completion messages for an older job after a new job has been selected. Recheck job ownership after fetching error details and before showing them.

This read-only decision has no queue or preallocation changes. Existing per-operation history, authorization and RQ polling endpoints remain in place. No new access surface is introduced. Compare the local receipt with the actual job argument and function before selecting its ID. Display filenames as text. A rejected submission must not set a new selected job. Security impact is low.

## Independent review disposition

The paired-receipt proposal would have required additional rollback after ambiguous RedisPrep publication and lost admission leases. The agreed incident repair instead reads existing receipts, verifies their RQ ownership, and uses neutral unavailable status whenever ordering is ambiguous. Reviews also distinguished the currently rendered summary from durable build artifacts. The latter needs its own publication fix. The panel preserves its rendered summary, uses only server-confirmed filenames, and filters stale job messages and their asynchronous error details. Report responses use request ordering to keep a delayed load from replacing the newer summary. Lookup outages refer to RQ after RedisPrep references were read.
