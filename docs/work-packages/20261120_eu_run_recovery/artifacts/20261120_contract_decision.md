## Proposed first implementation scope

- **Climate upload:** Derive the mode from the successfully validated and published active CLI. A failed replacement preserves the previous successful file and matching metadata. Resolve existing mode/file mismatches from the actual active upload and persist the correction on the next authorized mutation. An absent or unreadable active file produces an actionable climate-input error. A report page load does not write run state.
- **Climate job display:** Choose the latest admitted build or upload by authoritative server-side admission order. Preserve both job history entries. On reload, bind status and details to the selected attempt. Render any previously committed summary with its own identity when the latest attempt failed. Describe expired job details as unavailable.
- **Deprecation:** Allow genuine uploaded single-storm climates and existing single-storm runs through normal WEPP execution where the existing native and downstream paths can be verified. Warn users that the mode is deprecated. Keep the scope of new generated-storm authoring, batch execution, and continuous-only report availability explicit. Accept the transition only with real event output and clear report behavior.
- **E-OBS:** Treat the installed raw and scaled E-OBS NoData sentinels as missing for rainfall and temperature. Preserve cubic behavior on complete valid neighborhoods. Determine bounded sampling behavior at incomplete neighborhoods with incident, land-interior and no-support controls. Report unavailable coverage with dataset, location and month. Validate generated daily records and monthly precipitation. Require an ADR for the interpolation policy.
- **European land use:** Bind gridded CORINE to its own compatible mapping. Validate uploads against their declared code namespace and Disturbed requirements. Keep a user's compatible uploaded selection scoped to that upload workflow. Issue an actionable error naming the source, mapping and offending classes, and preserve the last complete build for failed replacements. Validate the ESDAC catalog as a whole, including the nine Disturbed severity destinations.
- **Migration:** A partial first build or failed replacement alone does not make a current-schema run eligible for land-use migration. Continue migrations for complete authoritative legacy data and applicable old schemas. Exercise migration in both dry-run and real legacy control paths.

## ESDAC Advanced options contingency

When review cannot establish a defensible source-backed recovery for a required missing subsoil, expose editable subsoil defaults in Soil Options → Advanced options for the gridded ESDAC path only. Start with one fixed loam preset. Prefill it on fresh and existing ESDAC projects without saved values. Do not query a raster or run a build to populate the form. Apply its six values as one coherent material only when the source subsoil is demonstrably missing. Preserve valid existing subsoil and target topsoil, depth, CEC, and applicable hydraulic lookups. A shallow profile that does not emit subsoil never consumes these values. Required data failures outside the missing subsoil material still fail with field-level guidance.

The UI, admission and worker use the same resolved ESDAC build eligibility, including fresh and failed runs, mode switches, read-only projects and requests that omit the mode. Use the existing dispatch precedence for soil maps, ISRIC, specialty modes and locale capability authority. The persisted `soil_source` identifies a prior output and is cleared before a build, so it cannot control visibility. The UI labels units and explains that the values are used only when ESDAC lacks required subsoil data. The route validates all six fields before mutating project state. Require finite admissible material values, positive bulk density and physically balanced texture. Persist validated project choices with the accepted build inputs. Bind the fully validated six-field profile to the admitted build attempt so intervening submissions and edits cannot alter the input a worker consumes. Failed enqueue and rejected admission preserve the last accepted configuration and completion markers. Use the established tracked RQ job and input ownership boundary. Existing ESDAC runs without saved choices use the approved initial defaults when this path applies. The quality report and generated soil provenance identify each affected hillslope and the substituted profile. Verify state retention, retries, existing reports, Disturbed preparation and WEPP readback. Preserve authorization and unrelated soil paths.

The operator selected fixed application defaults. The starting profile is 25% clay, 40% sand, 35% silt, 1.4 g/cm³ bulk density, 0.5% organic carbon and 5% gravel. They are generic modeling values. ## Existing 7778 consumer boundary

The configured 7778 transform can generate a soil that the ESDAC downstream validator rejects because the native 7778 schema does not serialize the 9002 land-use and texture fields. The same mismatch reproduces with an unchanged accepted base soil. Keep the current configured format and native numerical contract. Define format-specific metadata verification based on actual serialization and validate required run provenance, physical invariants and exact downstream WEPP inputs. Do not treat absent required 9002 metadata as valid. Review both single- and multiple-OFE writer consumers. [Generated controls](20261120_esdac_disturbed_format_controls.json)

The 7778 diagnostic files preserve the writer's requested `luse` and `stext` in the generated replacement-provenance comments. The proposed validator reads those values from the last recognized 7778 Disturbed migration block when that provenance is required. Validate the expected values with an exact comparison and reject missing, ambiguous or mismatched fields. Continue validating 9002 and later native fields in their parsed records. Apply this only to ESDAC transformed members with required expectations. Keep base copies, management-supplied files and final MOFE stack physical checks in their existing format-aware scopes. Validate each transformed MOFE member before stacking. A final stack comment cannot establish member-level provenance. Test genuine archived format controls and require an explicit disposition for old transforms without the expected provenance.

## Initial independent review disposition

The six-field replacement now requires all six source fields to be exactly zero. An independent raster readback confirmed this signature for all 37 original rejects. Cases with a nonzero, unavailable or malformed source field remain governed by the existing source validation. The fallback marker in a generated soil is stable and participates in content equivalence, so provenance is not discarded by retry deduplication. A per-hillslope report retains original field values and the chosen profile. Add regression controls for unchanged soils and reuse alongside the writer and serialized-consumer checks.

The checkpoint also incorporates admitted-attempt ownership, shared ESDAC source eligibility, and format-specific member, copy, and stack validation from independent review. Final acceptance and reviewer confirmation remain pending.

The second review independently reproduced a same-key MOFE issue before any edits. Distinguish members already on disk from members scheduled in the current build. Verify a fresh repeated-key stack and retry. Preserve explicit ESDAC source identity across the batch handoff so adding profile parameters cannot bypass the downstream quality report.

The operator confirmed on 2026-11-20 UTC that one prefilled project profile applies automatically to every eligible ESDAC hillslope, with fixed starter values available without running a soil build. Independent reviews prior to this clarification remain implementation inputs. The checkpoint records the final review and conformance separately.

The operator requested an explicit warning when defaults were actually applied. Reuse the existing warning style used by the [Climate build summary](../../../../wepppy/weppcloud/templates/reports/climate.htm) through the shared `wc-alert wc-alert--warning` classes. Show “Subsoil defaults applied” above the Soils summary coverage table with the affected and total hillslope counts and accepted build details. Announce it politely when a successful build refreshes the summary and show it again on reload. A failure must never create or relabel the warning for a different attempt.
