## Required admission API and evidence

| Requirement | Acceptance evidence |
| --- | --- |
| Explicit `pilot_id` is the sole bounded exception while general async is false | Authorized pilot calls succeed; absent/unknown/expired/stopped ID and excluded scope calls fail closed without job creation. General configuration stays false on scheduler and every eligible worker. |
| Immutable exact scope allowlist | Durable manifest hash binds canonical locator, scope/incarnation and owner identity under existing roots; no glob or prefix authorization. Resolved-path substitution, symlink escape, replaced incarnation and manifest edit are rejected by local regression tests. |
| Inventory isolation | Inventory starts from exactly the allowlisted locators, never `/wc1/runs` or its `qc` directory. Every discovered/emitted/admitted locator belongs to the manifest. A new child under an allowed directory is not implicitly authorized. |
| Global outstanding bound | Atomic admission ledger counts all catalog maintenance states: reserved, queued, deferred, scheduled and started, across every admission path. Observed and ledger outstanding never exceed seven or the current compatible-consumer bound. Worker loss alone never releases a permit. |
| Cumulative budgets | At most 25 refresh attempts and two inventory attempts, including retries. Same-ID automatic retry must not bypass the debit. Count unique IDs and actual execution attempts separately; failed/reserved attempts cannot reset budgets on controller restart. |
| Finite authority | New admissions stop no later than 30 minutes from the immutable pilot start, and immediately on operator stop or ordinary waiting work. Controller/monitor loss must prevent further admissions through the reviewed fail-closed mechanism; no new daemon is proposed. |
| Stop does not corrupt work | Stop closes admission, preserves receipts/checkpoints and permits owned admitted jobs to drain. Resume is an explicit operator action within remaining authority/budgets; it does not silently renew the deadline. |

The companion [implementation specification](20261027_bounded_pilot_implementation_spec.md) proposes an installed register/status/tick/pause/resume CLI and explicit `pilot_id` admission/worker arguments. Exact signatures and receipt schema must be frozen at the checkpoint. Controller-visible state needs manifest/configuration hashes, deadline, paused/stopped reason, cumulative debits by kind, active exact job IDs and attempts, and denial reasons. Unknown/unreadable ledger or queue state cannot be interpreted as zero load. Permit release must rely on terminal/cancellation evidence, not disappearance from one registry.

## Controller phases after checkpoint approval

1. **Preflight:** retain exact deployed commit/source hashes, participant configuration and identity/mount readbacks; require all eight intended consumers healthy and compatible. Take an ordinary-queue baseline and refuse to start with waiting ordinary work or unavailable monitoring. Confirm global async false and the immutable pilot ledger starts with zero debit. 2. **Negative controls:** exercise absent/unknown pilot IDs and the excluded sentinel through the public internal admission interface. Assert no new maintenance job, permit or scope mutation. Do not probe real unrelated projects. Local concurrency/security regressions must already cover replacement/escape/retry/budget/controller-loss cases; do not inject worker deaths or configuration mismatch into production.
3. **Receipt-free inventory wave:** leave the eight allowlisted scopes without catalogs/refresh receipts, then request one actual pilot inventory job seeded only with their locators. Use real reconciliation/admission entry points and shared `batch`; all refresh work must carry pilot authority. Observe cumulative/active limits throughout. Record inventory output locators and receipts/admissions before validating artifacts.
4. **Receipt/admission wave:** after the first wave drains and passes raw artifact readback, create fresh owned receipts for existing copied assets through the reviewed receipt primitive (`record_catalog_refresh`) and request explicit pilot admission. Normal `request_catalog_refresh` remains synchronous while general async is false; do not change that behavior or claim this pilot exercises ordinary asynchronous producers. Source bytes need not change to test receipt acknowledgment; report this limitation explicitly. Exercise coalescing with repeated requests for the same scope and verify receipt IDs are acknowledged by the matching publication. Do not manufacture scientific data or lower queue/job timeouts to force a pass.
5. **Bounded recurrence:** if the reviewed API requires a second inventory attempt to prove checkpoint/resume or revisit behavior, consume the second inventory budget explicitly. It must seed only the same frozen locators and must not regenerate a fleet-wide discovery frontier. Budgets are ceilings, not a requirement to spend all 25 refresh attempts. Retries consume remaining budget and can prevent later phases.
6. **Close admissions and drain:** stop the pilot before final acceptance readback, allowing admitted work to finish. The 30-minute admission window is not a completion deadline. Observe until all pilot jobs/permits are terminal or retain an explicit blocked-drain finding. Do not kill ordinary jobs, delete shared queue keys, or unlink guard files.

## Ordinary work monitoring and stop conditions

Use raw queue/job/registry and worker readbacks, not only dashboard queue counts or retained-history means. Start monitoring before admission and continue through drain. The canonical observation cadence is ten seconds, with a sixty-second owned observation lease; the admission decision itself must inspect ordinary waiting work atomically under its reviewed policy. Polling cannot prove absence between samples.

Keep raw ordinary job IDs/timestamps/registry transitions in a private operator evidence directory. Repository artifacts retain digest-only ordinary identifiers and aggregates, never arguments, project paths or tracebacks. Preserve enqueued/started/ended timestamps and current wait ages; classify maintenance by the canonical reserved prefix before deserializing payloads. Track arrivals, starts, completions, queued/started catalog counts, ordinary oldest wait, compatible consumers and pilot ledger debits together.

Stop further admissions on any ordinary waiting backlog, a five-minute ordinary wait, configuration/identity mismatch, missing monitor evidence, artifact failure, unauthorized locator, or unexpected count/permit growth. The five-minute threshold is a pilot failure trigger, not a promise that in-flight work finishes within five minutes; a backlog stop may occur earlier. If no ordinary arrivals occur, report that delay-under-competing-arrivals was not exercised. Do not submit an artificial scientific job merely to manufacture an ordinary-work sample without separate authorization.

Admission must remain stopped after a trigger; allow existing work to drain and retain the triggering samples. Observation gaps or inability to attribute concurrent ordinary work prevent a clean noninterference claim. Seven outstanding jobs do not establish a permanently reserved worker or a response-time guarantee.
