## Security triage and scope

- Security impact: **high**; dedicated review required by the [work-package gate](../../README.md#security-review-gate).
- Surfaces: managed/standalone path resolution, catalog publication and incarnation, archive/restore/fork/delete/readonly, batch admission and recovery, worker capabilities, public maintenance polling, HTTP/MCP query source authorization, and native scanner release provenance.
- Authority: [canonical refresh contract](../../../schemas/query-engine-catalog-refresh-contract.md). This artifact supplements the [contract security review](2026-10-23_security_review.md), [implementation correctness review](implementation_correctness_review.md), [implementation QA review](implementation_qa_review.md), [execution ledger](execution_evidence.md), and [environment probes](2026-10-23_environment_probes.md).
- Threat assumptions: project files and retained queue records may be malformed; Redis payloads do not establish filesystem authority; all participating publishers/lifecycle paths must use common coordination. Arbitrary host-level adversaries that ignore filesystem ownership/guards are outside the cooperative locking guarantee.
- Valid states retained: absent legacy refresh metadata; standalone synchronous directories; managed nested scopes and authorized parent-backed sources; missing/expired maintenance jobs; existing readonly catalogs; explicit manifest-owned combined-viewer preparation/rollback. Production identity and workflow parity are not inferred from temporary-directory tests.
