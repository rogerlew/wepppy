## Test quality and maintainability

The focused tests generally assert useful observable behavior: streaming limits
and temporary-handle closure, immutable generation retention, explicit error codes,
source preservation after failure, selected-source HTML escaping, restored mode
transport and actual generated OFE ordering. The twelve-OFE case deliberately
distinguishes OFE 10 from its neighbors, so it detects the former lexical-sort bug.
The active-initial-condition fixture verifies an uploaded source can reference a
nonfirst scenario and still receive cover overrides without changing source bytes.

The small fake `SourceController` is suitable for deterministic filesystem and
publication-failure tests, but cannot prove actual NoDb/cache/Redis behavior. The
new [real publication-failure evidence](20260926_publication_failure_acceptance.json)
addresses that distinction for both domains before and after durable dump; the
script checks durable pointers, the in-memory pointer, previous generations and
readable selected bytes. The [download evidence](20260926_download_acceptance.json)
checks authenticated Browse listing and exact source hashes.

The artifact-test matrix now states uploaded-soil versus catalog-soil intent
explicitly and asserts the requested saturation in every prepared soil OFE.
The refresh test uses a file sentinel; its name/evidence should not imply a real
controller-metadata round trip.

The new reference fixtures use unequal contour/drainage counts and distinct values
across OFEs, testing deduplicating and ordinary synthesis. They assert references
after persisted summary reload, actual segment materialization and prepared-file
validation, then execute the certified binary. A separate case preserves the
legacy interpretation. The reviewer edited tests and these review records only.

## Evidence limits

- [Browser evidence](20260926_browser_controls.json) uses real accepted NoDb
  control partials and shared CSS in Chromium across three themes. It proves
  visibility, Tab traversal to each chooser, native chooser selection and unchanged
  accepted feedback before submission. The rerun records
  `keyboard_tab_reachable=true` for both inputs in all three themes. The script
  does not load the full controller bundle, click Build, submit through browser
  authentication, or test read-only interaction. Do not describe it as a complete
  browser upload workflow or full keyboard/accessibility certification.
- Artifact tests use real parsers, synthesis and generated-file reads with
  lightweight controller/watershed fixtures. Native execution evidence covers
  two and twelve OFEs; the owner also added a 32-OFE native regression. The three
  independently executed reference cases use two OFEs and controlled
  topology/climate. Parser boundary fixtures cover the certified maxima, but
  native execution does not certify every permitted section/event combination.
- Admission-conflict evidence uses real Redis jobs/receipts and NoDb locking,
  but intentionally constructed queued receipts are distinct from a timing race
  between independently executing workers.
- The unrelated-target fork passed functional summary access. The preexisting
  source-prefix destination rewrite defect remains recorded in the correctness
  review and is not repaired by SUDI-01.

No additional broad refactor is required by this review. Keep the strict parser,
publication helper, project policy and route transport boundaries separate, and
retain the explicit scope of each acceptance artifact.
