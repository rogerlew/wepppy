# S01/S02 receipt performance checkpoint QA

Disposition: **ratify the bounded component budgets below for implementation**.
Root accepted these measured proposals. This is pre-implementation evidence,
not an implemented-path pass or whole native/HTTP runtime acceptance. No
production or test files were changed by this review.

## Evidence and scope

`benchmark_sbs_receipts_profile.py` and
`sbs_receipts_profile_performance_baseline.json/.log` retain the script, every
sample, read counts, module hashes, and limits. Large fixtures and source
snapshots remain browsable at
`/wc1/batch/qa-sbs-receipts-89a2b9544fb5/benchmark-manifest.json`.
The run completed under UID 1000/GID 993 with all named-input versions/hashes and
measured modules unchanged. All native/controller/copy operations used unique
disposable paths; named originals received only ordinary reads. No HTTP or job
submission occurred.

Actual uploads: Grizzly Creek 599,196 bytes (714 × 836), Rattlesnake 747,242 bytes
(933 × 789). A separate **stress fixture**, not an actual upload, is a valid
16,779,862-byte 4096 × 4096 uncompressed Byte GeoTIFF generated by nearest
resampling of copied Grizzly class pixels. Copies prime filesystem pages;
helper-cold and actual 512-entry eviction do not mean cold storage. Gates are
local mean budgets, not percentile or storage-service guarantees. They impose
no new upload size limit; larger supported files require size-aware evidence.

Five repeats cover ordinary operations; settled signatures/skips use 30, actual
512-entry eviction uses three per fixture, and each first initialization uses
one. Controller initialization is measured separately. The existing assembler
measurements use real copied NoDb hydration, event append, config handling and
legacy snapshot logic. The fixture config branch writes active-config/default
seeds but lacks the primary `config.cfg`: Grizzly's named original has a
34,830-byte primary config, while Rattlesnake's original lacks it. Final initial
capture must include the complete configured source and this extra copy; its
budget is a proposal with headroom, not an initialization acceptance pass. Python read counters exclude `shutil` kernel fast-copy
reads; those copy operations still transfer the full main file.

## S01 measurements and gates

All times are milliseconds. “Real” spans the two actual uploads.

| Operation | Real mean | 16 MiB stress mean |
| --- | ---: | ---: |
| Existing definition-only signature | 0.016–0.040 | 0.017 |
| Receipt/signature, settled | 0.626–0.649 | 0.215 |
| Receipt/signature, helper-cold | 3.425–5.521 | 69.107 |
| Receipt/signature, actual 512-entry eviction | 2.598–3.282 | 60.762 |
| Receipt pre/post skip, settled | 0.854–1.213 | 0.438 |
| Receipt pre/post skip, helper-cold | 5.905–6.701 | 112.230 |
| Existing actual mode copy/consume | 7.916–9.168 | 88.990 |
| Composed receipt/copy/consume/two admissions | 29.275–34.550 | 459.481 |

The existing copy baseline calls `apply_scenario_mode`; native validation,
landuse/soil builders and their directory-lock wrapper are explicit seams. The
composition performs initial and pre-reset source hashes, an opened-source
hash/copy, independent child verification, conditional source-version check
before unlink, then outer and locked-admission-equivalent child checks. It
retains physical child versions separately from content. It reads exactly six
main-file equivalents. No native work or actual metadata lock is inside this
composition, and this prototype does not certify the final security protocol.

Ratified implementation gates:

- Complete SBS receipt pre/post reuse component: mean ≤10 ms settled with zero
  digest payload reads; ≤30 ms helper-cold/evicted for each real fixture and
  ≤200 ms for the stress fixture.
- Complete initial-receipt, verified-copy/consume and admission-check component:
  mean ≤75 ms real and ≤650 ms stress, including the actual implementation's
  required checks. Preserve baseline copy/write/access behavior.
- Final acceptance must time actual direct and queued call paths and report
  whole native runtime and metadata-lock residence separately. The component
  budget is not a cap on clone/reset, native validation, generated landuse,
  soils or WEPP execution, nor permission to omit checks inside the lock.

The stress copy composition adds about 370 ms over the existing copy. A blanket
small-file threshold would hide this cost. Settled ordinary-file digest reuse
already avoids repeated payload reads; no new cache, lock or receipt datastore
is justified by these observations.

## S02 measurements and gates

| Operation | Real mean | 16 MiB stress mean |
| --- | ---: | ---: |
| Actual controller first lookup (separate) | 19.117–38.726 | 22.391 |
| Actual controller settled lookup | 0.091–0.218 | 0.081 |
| Existing assembler first event/config capture | 39.265–42.810 | 154.155 |
| Existing assembler established draft/event | 14.148–14.513 | 67.938 |
| Established draft plus composed event receipt | 32.553–32.913 | 283.020 |
| Existing actual form selection + Requests preparation | 1.391–2.360 | 41.625 |
| Composed receipt/bytes verification + Requests preparation | 5.022–6.309 | 95.789 |

The capture composition preserves real append/config/legacy snapshots, adds the
new expectation marker to the appended event, creates visible status, copies
and hashes the selected main through one opened source, verifies the output,
then atomically replaces the complete receipt. It reads two additional main
file equivalents. Fresh-controller and first-draft costs are separately measured;
a first-draft **composed** capture was not timed. Its gate includes measured
initialization costs with headroom and must be checked on the final code.

Playback composition reads and validates receipt/path/length/hash and opened
file versions, then passes those same retained bytes to actual Requests
multipart preparation. Both old and composed wire bodies were parsed locally;
file SHA-256, `input_upload_sbs`, and `application/octet-stream` match. The
accepted `.tif` suffix is preserved. Both paths read one payload; verification
adds CPU/metadata work, not a second payload read.

Ratified implementation gates:

- Actual complete event capture, established draft: mean ≤100 ms real /450 ms
  stress, including owner lookup, append/config/legacy work and new receipt.
- Initial controller/draft/config capture: mean ≤125 ms real /550 ms stress.
  Measure final complete first capture; the prototype does not count as that pass.
- Complete event-bound form preparation through Requests multipart encoding:
  mean ≤20 ms real /150 ms stress; retain exact selected bytes and existing
  form/MIME/extension behavior. Network/server/native processing are separate.
- Final accepted byte preparation should read the retained payload once and
  avoid an additional full-size retained copy beyond the existing Requests
  buffering. Observed Python allocation peaks are 35.69 MB existing and
  35.66 MB composed for the stress fixture (about 2.13 payloads). This measures
  Python allocations, not process RSS. Report final peak allocation rather than
  inventing a memory limit or changing supported upload sizes.

Each new event retains approximately one main-file size plus a small receipt,
in addition to legacy snapshots. Repeated equal-byte events still have distinct
identities. Record aggregate profile seed growth and apply the existing profile
seed/LFS review guidance; this does not authorize dropping events or adding a
new runtime cap. Promotion/archive and real `wctl run-test-profile` acceptance
remain required on a disposable original and sandbox.

## Quality and remaining gates

Keep source observation/copy and receipt validation cohesive; do not duplicate
slightly different hashing rules between direct execution, workers and playback.
Preserve append-before-fallible-capture and explicit malformed/failed evidence.
The prototype intentionally does not establish all symlink/receipt publication
race controls or execute locks/native models. Correctness/security contract
ratification and final actual implementation benchmarks remain required.
Whole-package browser/runtime acceptance remains open.
