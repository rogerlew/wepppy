## Maintainability and test robustness

`final_code_quality.md/.json/.log` are **observe-only** telemetry against
`origin/master`, not a merge gate or proof of this task alone. The report covers76
changed files, with12 highest-red and17 highest-yellow classifications and59
worsened metric entries. `radon` is unavailable: Python cyclomatic complexity is
unknown, not zero. No dependency was installed to fill that optional metric.

Small focused helpers keep distinct responsibilities visible: ordinary-file
digest acquisition, raster observation versus read guards, CLI retained snapshot
publication, report proof/publication, event-bound SBS seed bytes and Omni
execution/reuse admission. They preserve owned numerical readers and existing
authority. Similar hash loops are intentional where openers, returned identity,
error contracts or caching rules differ; they do not justify a universal wrapper.

Material growth remains in existing orchestration modules. The reported longest
Omni service function grows217→265 lines, RQ Omni261→285, postfire production
file598→732 SLOC, Features service3026→3099 and D-Tale1013→1135. The immediate
reason is explicit generation/admission/failure state and preserved existing
ordering. The new helpers remain comparatively small. This is debt to manage,
not a reason to refactor stable flow during runtime acceptance.

Low-risk follow-ups, when these boundaries next change:

- `features_export/service.py`: extract the companion producer-proof validation
  block before adding further companion branches; retain sequential publication
  and immutable failure artifacts.
- `postfire_debris_flow/production.py`: name intermediate content/metadata
  comparison values in `_current_authority`/`get_state` to make policy easier to
  read, without merging access/digest/download lifetimes.
- `omni_sbs_freshness.py`: type receipt dictionaries and version tuples; retain
  the separate execution/reuse guards and durable refresh transaction.
- `profile_recorder/playback.py`: describe the intentional `Path | SbsSeed`
  file-tuple union accurately. The `.pyi` public surface is a separate contract.
- `webservices/dtale/dtale.py`: reuse the existing shared-overlay update/removal
  helpers for future map features rather than adding registry mutations.
- Report compatibility currently recognizes one narrow translator error text;
  use a typed missing-resource error if that owner later provides one. Do not
  widen the fallback now.

Meaningful tests assert native rows/classes/geometries, exact previous artifact
bytes, real NoDb persistence, real permission denial under UID1000/GID993,
deterministic before/after replacement and ABA scheduling, provenance identity,
actual failure retention and descriptor cleanup. Test-clock control covers cache
age while real-clock rewrite probes preserve timestamp collisions. The report
barrier and opened-descriptor replacement cases prove generation behavior rather
than merely comparing two equal concurrent outputs. Synthetic fixtures are
explicitly bounded; independent probes using actual shared locks and native
readers supplement them.

Some useful controls remain executable retained probes rather than ordinary
regressions: archive chmod/legacy metadata failures, selected D-Tale access/error
cases, profile/SBS authority edges and Features parent/companion chains. Promote
those exact cases when extending the relevant code. Final affected test counts
have different scopes and revisions and must not be summed as one complete run.
