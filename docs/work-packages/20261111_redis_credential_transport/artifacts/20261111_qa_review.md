## Findings

1. **High — native RQ pool arguments were discarded; source corrected, regression
   evidence pending.** The initial `Connection.__init__(**_rq_defaults)` always
   rebuilt from environment. Installed RQ's `worker_pool.run_worker` and
   `scheduler` reconstruct this class with `connection_pool`; additionally
   `wepppy/rq/webhook_hooks.py:_bounded_connection` passes a pool with short
   timeouts and disabled retries. Discarding it removed the hook's latency bound.
   The revised `wepppy/config/rq_redis.py` uses an identity marker only for RQ
   config construction and forwards native arguments otherwise. Add a direct
   test that the supplied pool is retained with its timeout/retry settings, plus
   an installed-CLI test of the empty `--url` environment override.

2. **Medium — dev/HPC healthchecks did not require PONG; source corrected,
   executable negative evidence pending.** A `redis-cli` Redis error response can
   leave the process successful without a PONG. Both changed dev/HPC checks now
   use `grep -qx PONG`, matching prod/canary. The focused source test checked only
   prod; runtime acceptance must exercise wrong and missing credentials against
   the changed wrapper/probe rather than infer failure from command spelling.

3. **Medium — password framing differed across shell and native clients;
   source corrected, retained parity suite pending.** Initial shell
   `[[:space:]]` accepted leading/trailing UTF-8 nonbreaking spaces rejected by
   Python/Go. The revised shell validates decoded codepoints and Go includes
   Python's additional U+001C–U+001F whitespace characters. Re-review directly
   exercised 65 shell/Python synthetic cases: leading/trailing Python whitespace
   codepoints below U+3100, valid multibyte/interior whitespace, LF terminators,
   invalid/truncated UTF-8, NUL, empty and embedded LF. Zero acceptance mismatches
   remained. Persist equivalent shared cases and include the Go/dashboard paths.

4. **Medium — password string subclasses leaked under format specifications;
   source corrected, real AUTH evidence pending.** Both `_Password` classes now
   override `__format__`. Re-review confirmed five native wrapper formatting
   cases (repr, str, empty format, `:s` and alignment) contain no synthetic canary,
   while `.encode()` preserves the original bytes. Retain those regression
   assertions and prove actual Redis encoding through the real AUTH cases.

## Maintainability and residual debt

The migration is reasonably bounded and uses existing client APIs; the CLI
adapter avoids a dependency fork. The manual UTF-8 state machine is security
sensitive and needs a shared table-driven framing test, including multibyte
boundaries, rather than only a handful of successful UTF-8 cases. The Python
resolver currently reads an explicit password file twice through different
normalizers; one owned read/validation path would reduce ambiguity and redundant
I/O without changing secret lifecycle.

Non-blocking polish: restore concise public type annotations in
`wepppy/config/redis_settings.py`, remove unused imports, and rename tests that
still describe injecting passwords into URLs. Update the status/preflight README
and AGENTS guidance plus `docs/infrastructure/secrets.md`, which still describe
injection, before the documentation handoff. Keep the two small dashboard/native
password wrappers behaviorally identical with shared test cases; a new packaging
abstraction is unnecessary for this change.
