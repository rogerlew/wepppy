# Account data compatibility and regression plan

Checkpoint: `9eb2dfcf0`; current Alembic head `f6b8d27a901c` (notifications). No production migration is authorized.

Add account_kind (shared/cilogon), contact_email, local_credential_state (legacy/none/pending/enabled), mailbox_verified_email/at, verification_nonce and verification_sent_at. Existing rows default shared/legacy without changing email, password, ID, uniquifier, roles, OAuth links or run memberships. New CILogon rows use NULL User.email, optional nonunique contact_email, no password, and state none. New local rows use normalized unique User.email, no password and state pending. No verification backfill from confirmed_at.

Retain existing User.email uniqueness and add a lower(trim(email)) unique index to prevent concurrent case-insensitive duplicate shared identities. Preflight legacy case-insensitive duplicates; abort migration before adding fields if present. Do not merge/delete or silently choose a legacy account. Report counts only for operator disposition. Downgrade refuses removal while nonlegacy/new account state exists; do not run old code against CILogon or pending records. Rollout requires coordinated migration then compatible web code; credentials remain inactive until acceptance.

Consumer inventory: Flask-Security local registration/login/reset/change/confirm and JSON endpoints are gated in owned account integration; email discovery stays on User.email, never contact_email. OAuth shared lookup filters class. Profile uses a display/contact helper; notifications/preferences currently tolerate missing User.email and must use explicitly verified contact only where mail is sent. Role operations must pass User object rather than email. Admin ID-based operations remain available; email operations continue to target shared users only. Run ownership/membership is by User.id. Browse/session/API authorization must remain ID-based; any email-dependent bootstrap/share feature needs explicit compatibility evidence and no contact-email identity fallback. Retain unsupported cases as release gates, never claim full acceptance from login alone.

Validation uses disposable populated database: old hashes/roles/run IDs unchanged; migration preflight on duplicate normalized email; repeated NULL-email CILogon rows and duplicate contacts; exact subject identity uniqueness; shared normalized-email race; account creation/link failure rollback; recovery isolation; token exact-address binding/replay/concurrent redemption; pending users cannot obtain local sessions/tokens. Real mounted consumer and model output behavior remain separate environment gates. No run-scoped data schema is changed.

Consumer repair evidence: role assignment passes the User object; token issuance omits unavailable login email; Bootstrap signs/resolves positive user IDs and eagerly loads detached roles/members; rq-engine tolerates NULL owner emails. Real ORM tests preserve run membership and deny removed collaborators. SQLite migration tests retain legacy hashes/IDs/membership and reject duplicate normalized login emails/unsafe downgrade. PostgreSQL upgrade, simultaneous redemption/unlink, and production-mounted execution remain rollout gates.
